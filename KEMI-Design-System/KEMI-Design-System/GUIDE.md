# KEMI · Freelance Platform

디자인 재사용 가이드 · 2026.10.23 수정 · 디자인 시스템 1.1 기반

## 00. 수정 기준과 우선순위

기준 문서는 reference/KEMI_Design_System_1.1.html입니다. 2026-10-23 합의에 따라 Primary Color는 Leaf Green #539863으로 정했습니다. 브랜드 대표색과 주요 행동색을 구분하며 일반 주요 버튼은 Leaf 700 #367345 배경과 흰 글자를 사용합니다. Hover는 #2C623A, pressed는 #245331입니다. Leaf Green 원색은 브랜드 포인트이며 작은 흰 글자 배경에 그대로 사용하지 않습니다.

그라데이션 CTA는 홈·홍보 영역에 제한합니다. 대표 서비스 예시는 작품 탐색 → 저장·문의 선택 → 문의 → 답변·상담 → 종료입니다. 아래 프리랜서 플랫폼 전환 제안과 기존 구매·계약·결제 예시는 재사용 참고이며 현재 제품 범위를 확정하지 않습니다. 다크 모드는 확장안입니다. 브랜드·토큰·가이드와 React UI는 이 통합 전달본에서 함께 제공합니다.

## 01. 활용 방향

서비스 이름과 기존 KEMI 로고를 그대로 유지합니다. 부드러운 녹색·라임, 넉넉한 여백, 둥근 형태, 절제된 그라데이션을 이어가고, 화면의 중심을 영상 상품에서 사람과 프로젝트로 옮깁니다.

이 문서는 브랜드 재사용 기준과 프리랜서 플랫폼 적용 제안입니다. 새 플랫폼의 기능 명세나 계약·결제 정책을 확정하는 문서는 아닙니다. 아래 화면명·문구·구성은 새 기획에 맞춰 선택합니다.

## 03. 이름·로고 사용

헤더와 푸터의 이름은 KEMI로 통일합니다. 설명 문구는 로고 이미지에 합성하지 말고 별도 텍스트로 작성합니다. 예시 소개는 “프로젝트와 전문가가 만나는 곳”, 예시 주요 액션은 “전문가 찾기”입니다. 모두 제안 문구입니다.

| 상황 | 파일 | 적용 기준 |
| --- | --- | --- |
| 밝은 헤더 | brand/svg/logo-primary.svg | 기본형, 비율 유지 |
| 어두운 헤더 | brand/svg/logo-on-dark.svg | 어두운 단색 배경에서 확인 |
| 단색 표현 | brand/svg/logo-mono-dark.svg 또는 logo-mono-white.svg | 배경과 명암 구분 |
| 심볼만 표시 | brand/svg/symbol-primary.svg | 별도 접근 가능한 이름 제공 |
| 앱 아이콘 | brand/svg/app-icon.svg | 기존 아이콘 형태 유지 |
| 브라우저·홈 화면 | brand/icons/ | favicon·apple-touch-icon·manifest 함께 복사 |

로고 색은 원본 에셋 값을 유지합니다. UI 팔레트에 맞추려고 로고를 다시 칠하지 않습니다. 로고의 짙은 색 #173F2E와 UI의 브랜드 잉크 #0F3D2E는 서로 다른 값입니다. 늘이기·기울이기·워드마크 전체 유리 효과를 피합니다.

헤더 너비 140–180px와 심볼 높이의 약 1/4 여백은 기존 패키지의 시작 제안이며 확정 규정은 아닙니다. 전달된 로고는 첨부 시안으로부터 재구성한 벡터입니다. 원본 제작 파일의 정확한 추출물은 아닙니다.

## 04. 색상·타이포·공간

| 역할 | 사용할 토큰 | 기준 |
| --- | --- | --- |
| 페이지·본문 | --surface-base, --text-primary | 밝은 중립 배경과 짙은 본문 |
| 카드·패널 | --surface-raised, --border-default | 전문가·프로젝트 정보를 담는 단색 표면 |
| 브랜드 대표색 | --kemi-leaf-green | Leaf Green #539863. 브랜드 포인트·넓은 강조 면 |
| 일반 주요 액션 | --action-primary, --button-primary-text | Leaf 700 #367345와 흰색 글자. hover·pressed 별도 토큰 |
| 홈·홍보 CTA | --gradient-cta, --button-marketing-text | Soft Energy 그라데이션과 짙은 녹색 글자. 작업 화면에서는 단색 버튼 |
| 선택·강조 | --action-primary-subtle, --accent-creative | 선택 상태를 글자·테두리로도 구분 |
| 흰 글자 강조 영역 | --emphasis-bg, --emphasis-text | 보완색 #36677B와 흰색 |
| 오류·성공·주의 | --status-danger, --status-success, --status-warning | 상태 문구·아이콘을 함께 사용 |

Ocean Blue #5487A0는 브랜드 장식색입니다. 작은 흰 글자 배경에는 보완색 #36677B를 사용합니다. 상태색과 10색 팔레트를 혼용하지 않습니다. 새로운 배경·투명도·그라데이션 조합을 만들면 실제 글자 대비를 다시 확인합니다.

글꼴은 Pretendard 계열, 없으면 시스템 글꼴입니다. Display 48/32px, Heading 28/24px, Title 20px, Body 18/16/14px, Label 14/12px, Caption 12px의 11개 역할을 정의했습니다. 줄높이·굵기·자간·모바일 제목 축소와 한국어 예시는 기준 HTML의 Typography를 따릅니다. Caption에는 중요한 조건이나 오류를 넣지 않습니다. 숫자·시간·금액은 tabular-nums, 긴 본문은 최대 70ch를 시작 기준으로 씁니다.

간격은 4·8·12·16·20·24·32·40·48px, 카드 라운드는 24px, 모달 28px, 버튼·필터는 999px입니다. 모션은 120·200·300ms이며 동작 줄이기 설정에서는 감소시킵니다. 촘촘한 계약·작업 목록에 모든 항목을 큰 카드로 만들 필요는 없습니다.

다크 모드는 확장안입니다. 상태색·크기·레이아웃 값은 구현 보완값으로 구분합니다. 현재 제품은 보완한 디자인 규칙을 기준으로 구현하고 실제 화면에서 확인하며, 다른 서비스로 옮길 때는 해당 서비스에서 다시 검토합니다.

## 04-1. 공통 UI 보완 규칙

- 같은 행동 묶음에서 주요 버튼 1개를 기본으로 하고 Secondary·Ghost·삭제 행동을 구분합니다.
- 버튼의 기본·hover·pressed·focus·disabled·loading, 입력의 기본·focus·error·disabled·readonly, 선택 요소의 선택·미선택을 정의합니다.
- 입력에는 라벨과 필수/선택 표시를 제공하고 오류 문구를 연결합니다. 오류나 재시도 때 작성 내용과 선택을 유지합니다.
- 모바일 0–599px, 태블릿 600–1023px, 데스크톱 1024px 이상을 기본 구간으로 씁니다. 페이지 좌우 여백은 16/24/32px, 콘텐츠 최대 너비는 1280px입니다.
- 로딩·결과·빈 결과·오류·재시도·부분 성공을 구분합니다. 성공한 문의는 유지하고 실패 대상만 재시도합니다.
- 아이콘은 16/20/24px, 텍스트와 간격 8px를 기본으로 하고 단독 버튼은 44×44px 터치 영역을 권장합니다.
- 썸네일 비율과 잘림, 이미지 실패 대체 표면, 영상 위 재생·저장·시간 표시의 충돌을 확인합니다.
- 키보드 포커스, 모달 닫기·포커스 복귀, 색 외 상태 표시, 200% 확대와 긴 한국어 줄바꿈을 확인합니다.

## 05. 프리랜서 플랫폼으로 옮기는 방법

| 기존 영상 서비스 예시 | 프리랜서 플랫폼 적용 제안 | 달라지는 정보·행동 |
| --- | --- | --- |
| VideoAssetCard | 전문가 카드 / 포트폴리오 카드 | 전문 분야, 소개, 작업 예시, 상세 보기 |
| AssetSearchBar | 전문가 검색 / 프로젝트 검색 | 분야·기술·가능 일정 등 기획으로 정의한 필터 |
| AssetFilterPanel | 검색 필터 패널 | 선택·해제·결과 수·조건 초기화 |
| VideoPreviewPlayer | 포트폴리오 미리보기 | 영상 작업물일 때만 재생 UI 사용 |
| CreatorMatchCard | 전문가 프로필 요약 | 전문 분야·소개·경력·작업 가능 여부 |
| OfferCard | 프로젝트 제안 카드 | 업무 범위·제안 금액·예상 일정 |
| DealTimeline | 협업 진행 상태 | 기획에서 확정한 단계와 다음 행동 |
| LicenseSelector / RightsDisclosure | 계약 조건 요약을 새로 설계 | 작업물 권리·수정 범위·납기 등 정책 필요 |
| PaymentSummary | 견적 / 결제 요약을 새로 설계 | 비용 항목·수수료·세금·지급 조건 결정 후 표시 |

이 표는 기능 구현이나 컴포넌트 제공 목록이 아닙니다. 기존 HTML의 시각 패턴을 어디에 참고할지 설명합니다. 새 플랫폼에 없는 기존 기능을 이름만 바꿔 넣지 않습니다.

영상 썸네일과 생성된 브랜드 장식은 필수 자산에서 제외했습니다. 직군에 맞는 포트폴리오 이미지를 사용하고, 작업물 권한과 인물 사진 사용 가능 여부는 실제 콘텐츠 기준으로 확인합니다.

## 06. 화면 구성 제안

| 화면 | 우선 보여줄 정보 | 대표 행동 제안 |
| --- | --- | --- |
| 홈 | 서비스 가치, 주요 분야, 탐색 진입점 | 전문가 찾기 / 프로젝트 둘러보기 |
| 전문가 목록 | 이름, 분야, 소개, 작업 예시 | 필터 적용 / 프로필 보기 |
| 전문가 상세 | 소개, 작업물, 협업 조건 | 문의하기 또는 제안하기 |
| 프로젝트 목록·상세 | 업무 범위, 예산 표기 방식, 일정, 필요한 역량 | 제안 보내기 |
| 내 작업 공간 | 진행 중 업무, 상태, 다음 할 일 | 상세 확인 / 다음 단계 수행 |

양면 플랫폼의 사용자 명칭은 “의뢰인 / 프리랜서”를 기본 제안으로 둡니다. 실제 대상에 따라 전문가·파트너 등 하나의 용어로 일관되게 정합니다. 위 화면은 선택 가능한 초안이며 전체를 MVP 범위로 확정한 것이 아닙니다.

## 07. Liquid Glass와 컴포넌트 상태

Liquid Glass는 작은 심볼·저장 포인트·일부 인터랙션 아이콘에 제한합니다. 프리랜서 플랫폼에서는 유리 효과를 억지로 늘리지 않아도 됩니다. 긴 본문, 검색 필터 전체, 입력 폼, 견적·계약·결제 표에는 불투명한 단색 표면을 씁니다.

주요 버튼은 기본·호버·포커스·비활성·처리 중, 입력은 기본·포커스·오류·비활성 상태를 정의합니다. 검색과 목록은 로딩·결과·결과 없음·오류·재시도를 구분합니다. 저장은 해제·저장을 구분하고, 문의나 제안의 성공은 실제 서버 응답 후 표시합니다.

색만으로 상태를 전달하지 않고 문구와 아이콘을 함께 둡니다. 링크는 이동, 버튼은 상태 변경에 사용하며 키보드 포커스를 표시합니다. 아이콘 버튼에 이름을 제공하고 hover 전용으로 핵심 행동을 숨기지 않습니다.

## 08. 개발 전달 시 결정할 항목

- 서비스의 주요 이용자와 한 문장 소개
- 전문가 탐색형·프로젝트 모집형 등 중심 이용 흐름
- 직군·기술·예산·일정 필터와 실제 데이터 구조
- 가격 단위, 협의 여부, 수수료·세금 표시 기준
- 계약·수정·취소·작업물 권리·정산 정책
- 검증 배지와 평점의 근거 데이터 및 노출 조건
- MVP 화면 범위와 로그인 전후 권한

결정 전에는 예시 금액·완료 건수·평점·검증 배지를 실제 서비스 성과처럼 표시하지 않습니다. 임의의 수수료·에스크로·환불 정책을 디자인 문서에서 확정하지 않습니다.

## 09. 적용 완료 확인

- KEMI 로고·파비콘·문서 제목·접근 가능한 이름이 일치한다.
- CSS와 JSON 토큰을 전달하고 기존 변수 충돌을 확인했다.
- 영상 구매·라이선스 예시를 새 서비스 요구사항과 대조했다.
- 데스크톱·모바일에서 내용 순서·줄바꿈·터치 영역을 확인했다.
- 키보드·오류·로딩·빈 결과·비활성 상태를 확인했다.
- 계약·결제·상태 문구를 실제 정책과 서버 동작으로 검증했다.

위 목록은 대상 사이트 개발 후 확인할 기준입니다. 이 패키지를 정리한 시점에 대상 사이트 구현·검증이 완료되었다는 뜻은 아닙니다.
