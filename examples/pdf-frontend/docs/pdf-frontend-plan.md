# PDF 기준 프론트엔드 구현

유일한 기능 요구사항: 루트의 `단계별_개발_계획.pdf` (5쪽). 다른 기능명세서, 과거 구현 기록 및 중첩 KEMI 프로젝트는 요구사항으로 사용하지 않는다.

## 범위와 경계

루트 npm workspace의 `apps/web`을 확장한다. 서버/API 계약·키·미결정 D01–D22의 세부 정책은 PDF에 없으므로 확정하지 않는다. 브라우저 내 시연 데이터로 기능과 상태 전이를 구현한다. 인증·PG 승인·환불·스토리지·AI·실시간 채팅·운영자 권한은 실제 연동이 아니다. 패스워드와 실제 개인정보를 저장하지 않는다. 로컬 데이터는 실제 권한 검증이 아니다.

## 구현 순서와 파일 책임

1. `apps/web/src/features/demo/model.ts`, `store.tsx`: 모집·의뢰·조건 버전·양측 서명·결제·자료·납품·수정·정산·취소 상태. Node 테스트로 단일 서명, 결제/준비 차단, 버전 고정, 분쟁 차단, 20만원 정산 예시 검증.
2. `Discovery.tsx`, `Campaigns.tsx`: 홈 작품/필터/상세/직접 의뢰와 모집 검색/작성/임시 저장/공개/제안/북마크. 빈 결과와 필수 입력 검증.
3. `Account.tsx`: 시연 로그인, 역할/이름 설정, 프로필, 공개 대표 패키지, 포트폴리오. 외부 로그인 미연결 표시.
4. `Workspace.tsx`, `Transaction.tsx`: 공통 대화/조건/준비/버전별 납품/리뷰, 결제 결과와 취소/부분 환불/보류/운영 기록. 양 역할을 전환하며 정상 거래와 취소 거래를 시연.
5. `App.tsx`, `Shell.tsx`, `styles/product.css`: 라우팅·탐색·알림·반응형 화면·실패/빈/로딩 상태. 빌드/타입/ESLint 및 브라우저에서 데스크톱/모바일 검증.

## 완료 판단

PDF의 각 프론트엔드 항목을 화면 또는 명시적 미연동 항목에 매핑한다. 정상 거래는 공개 모집/직접 의뢰 모두 공통 작업 공간을 사용한다. 검토 승인과 최종 수령을 분리하고, 결제/자료 미완료 및 분쟁 중에는 정산을 차단한다. 실제 서버·두 계정·외부 서비스·배포 검증은 로컬 시연 결과와 구분한다.

## 최종 상태

위 1–5의 로컬 프론트엔드 구현과 검증을 완료했다. 상태 전이 20개, Edge 브라우저 시나리오 16개, 타입/ESLint/포맷/빌드를 확인했다. 재현 방법, 단계별 기능 대응, 외부 연동·미결정 정책의 한계는 `pdf-frontend-guide.md`에 기록했다. 실제 서비스 완료나 배포 완료로 간주하지 않는다.
