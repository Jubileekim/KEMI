# 4-B 초안·완성 검토본 제출·영상 버전

기준: 기능명세 DEL-01/02(43~44행), WORK-03/04(69~70행)의 영상 조회·제출 안내 부분, P13/P14/P22, D17/D20. 계획 §4단계 두 번째 항목 중 초안/완성 검토본·버전 조회만 구현한다. 수정 요청·수정본·승인·최종 전달·수령·정산은 제외한다.

## 구현 순서와 성공 기준

1. 제출 모델: 초안/검토본·이전 버전 보존, 계약/작성자/시각, 수정 회차 미차감, 명령 ID/내용/작성자와 revision 대조.
2. 명시적 DEV MSW: 기존 양측 서명→전액 Mock 결제→제작 시작·필수 정상 준비를 업로드/제출 전 확인. 파일 준비와 정식 제출을 분리한다. 당사자만 목록/영상/안내 조회.
3. KEMI 공통 UI로 파일 선택·준비·설명·종류·제출, 버전 목록/플레이어·정확한 URL, 같은 방의 시스템 안내를 연결한다. 실패/유실/재시도/무권한/구버전/새로고침 경계를 검사한다.
4. 로컬 단위·build:web(타입/ESLint/운영 빌드)·형식·토큰·관련 데스크톱/모바일 E2E·운영 Mock 제외 검사 후 자체 변경 검토와 Draft PR로 전달한다.

## API 대조와 경계

- `docs/api문서.txt`, 현재 `apps/api/src`, `packages/shared/src`에는 납품·영상 버전·영상 접근·이벤트 계약이 없다. `/__mock__/deliveries/:contractId`, `/assets`, `/media/:versionId`, `/__mock__/delivery-events/:requestId`는 개발 전용 가상 계약이다. 실제 제품 API/DTO를 추가하지 않는다.
- MP4/WebM 1파일·300MiB·이름255자·설명2000자는 개발 메모리 입력 보호 예시다. D17의 파일 제한 단위/개수/형식/검사/미사용 파일/보존 정책을 확정하지 않는다. 업로드 실패 후 선택 파일을 보존하며 재시도는 새 준비 요청이다. 업로드만으로 제출 버전/안내를 생성하지 않는다.
- P13은 **제작자가 영상 자체 워터마크를 수동 준비**하는 기준이다. 완성 검토본 제출 시 이를 명시적으로 확인한다. 워터마크 자동 검사/합성·트랜스코딩은 없다. CSS 덧씌움으로 원본에 워터마크가 있다고 주장하지 않는다. 초안/검토본 모두 다운로드 버튼 없이 전용 플레이어로 조회한다. 코덱/손상은 재생 오류로 안내한다. 녹화·복제 완전 차단이나 실서비스 파일 보안을 보장하지 않는다.
- 파일 바이트·제출·안내는 단일 탭 메모리다. 새로고침 시 계약과 함께 초기화한다. URL은 정확한 버전을 지정하지만 새로고침 후 저장 복원은 실제 API/저장 계약 없이는 미완료다. 존재하지 않는 버전은 최신본으로 대체하지 않는다.
- 확정된 제출 버전에서 시스템 안내를 파생해 동일 사건은 한 번만 표시한다. 채팅 일반 메시지와 분리하며 사용자에게 시스템 메시지 입력을 허용하지 않는다. 업로드/실패는 안내를 만들지 않는다. 응답만 유실된 실제 Mock 확정은 재조회/동일 명령으로 복구한다. 인앱 알림 저장/읽음·외부 알림은 별도 미연결이다.
- 현재 WORK-03/04 전체 완료가 아니다. 기존 계약/결제/준비와 같은 방 연결을 유지하지만 PC/모바일 전체 작업 패널 재배치(D20), 다른 작업 이벤트·수정/승인·알림은 남는다. D11 수정 예외는 결정하지 않는다. 4단계 전체 완료가 아니므로 정상 수령→정산의 전체 단계 통합은 미실행이다.

## 실패·검토 관점

서명 없는 계약/타인/위조 Bearer는 조회와 미디어를 차단한다. 업로드/제출은 제작자만 허용한다. 미결제/시작 전/준비 문제 보류는 새 쓰기를 차단한다. ID 재사용·오래된 revision·같은 파일 재제출·다른 계약/작성자 asset을 거부한다. 요청 본문 처리 후 세션 epoch/상태를 다시 확인하고 최신 저장본에 적용한다. 결과 미확인은 새 제출을 잠그고 재조회/동일 요청을 제공한다. 실제 서버 트랜잭션·권한·영구 저장/다중 탭·악성 파일/서명 URL·서버 시각은 미검증이다.
