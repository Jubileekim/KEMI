# 2-B 선택 AI 분석·명시적 예산 반영

기준: 2026-10-24, `케미 기능명세서.xlsx` AI-01/02·P20·D16, 계획 §2단계, 기술 스택 PDF, 현재 API/shared. 구현은 `apps/web`의 기존 2-A 개발 전용 편집기에 한정한다.

## 구현

- 제작 조건을 별도 입력하고 선택 실행한다. 다른 캠페인 필드·예산·참고 자료·파일을 자동 전송하지 않는다. 개인정보·비공개 자료를 제외하도록 안내한다. 사용자가 직접 입력한 텍스트의 개인정보 자동 판별 기능은 없다.
- TanStack Query mutation·Axios·AbortController와 shared 요청 스키마를 사용한다. 자동 재시도 없음. 대기·취소·권한·호출 초과·서비스/네트워크 실패·잘못된 형식 모두 수동 예산/저장을 막지 않는다.
- 항목·수량·단가·소계·합계·산정 이유·가정·참고 한계를 표시한다. Zod 구조 검사 및 수량×단가=소계, 소계 합=합계 검증 후에만 반영할 수 있다.
- 리포트 생성은 예산을 변경하지 않는다. 사용자가 반영액을 확인·조정하고 **확인한 금액을 예산에 반영**해야 예산 입력란이 바뀐다. 저장·공개는 기존 별도 동작이다. 이후 수동 변경도 허용한다.
- 공고 조건·분석 설명이 바뀌면 이전 결과 반영을 막고 재분석한다. 지연 응답에도 입력 스냅샷을 비교한다. 재분석 실패 시 이전 결과를 재사용하지 않는다. 화면 이탈/로그아웃 시 요청 취소·세션 epoch 확인으로 늦은 결과를 차단한다.
- 마지막 적용액·리포트 ID·입력·결과·고정 Mock 모델/프롬프트 버전을 모의 초안에 연결한다. 수동 예산 변경 후에는 과거 적용 기록임을 표시한다. 기존 계약액과 연결하지 않는다. 공개 후 편집은 2-A와 동일하게 차단한다.

## 기능별 API 대조

| 기능  | 문서 스냅샷                      | 현재 저장소                                                                                    | 이번 연결과 경계                                                                                            |
| ----- | -------------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| AI-01 | `docs/api문서.txt`에는 경로 없음 | `POST /api/pricing/analyze`, `packages/shared/src/pricing.ts`, API pricing router/service 존재 | shared 설명 10~5,000자·구조·단가/수량 제약 재사용. 실제 API 호출 대신 `/__mock__/pricing/analyze` 고정 응답 |
| AI-02 | 별도 반영 API 없음               | 분석 응답의 참고 합계 존재. 리포트 ID/저장/버전/공고 연결 계약 없음                            | 로컬 폼 명시 반영과 `/__mock__/campaigns`에 마지막 적용 기록 저장. 실제 서버 공고/계약 변경 없음            |

기능표의 “API 정의 없음”은 문서 스냅샷 기준이며 저장소 코드에 API가 없다는 뜻이 아니다. 기존 분석 API는 활성 CLIENT 인증·사용자별 시간당 10회 제한·서버 경유 OpenAI 호출을 구현하고 있다. 이번에는 그 코드 존재와 계약만 읽었으며 실행/제공자 검증은 하지 않았다. 기존 제한을 D16 팀 승인으로 취급하지 않는다.

현재 shared 응답은 단일 참고 금액이다. 비용 범위·누락 정보 전용 필드·실제 모델/프롬프트 버전·분석 기준 출처·보관/재조회·리포트 적용 기록 계약이 부족하다. 범위나 버전을 추정해 실데이터처럼 생성하지 않는다. 화면의 누락 안내는 고정 Mock 가정이고 실제 분석 결과가 아니다.

## 미결정과 실제 연결 전 남은 일

- D16 입력·출력·금액 범위·저장·재분석·호출 한도 합의. UI의 적용액 1~10억 원·문자 보호 한도는 기존 분석 출력 상한에 맞춘 Mock 후보이며 공고 예산 정책 확정이 아니다. 응답 안내 1,000자 보호 한도도 로컬 검증 경계다.
- 리포트 식별/버전/근거/비용 범위/누락 정보와 실제 공고 적용 기록·권한·보존 계약 조율. 현재 단일 탭 모의 메모리는 새로고침 시 초기화된다.
- 실제 서버 Origin·인증·OpenAI 성공/실패·실제 제한·DB 저장 검증. 현재 편집기 전체가 2-A API 조율로 운영에서 준비 안내이므로 분석도 운영에서는 노출/호출되지 않는다.
- 공개 공고 핵심 변경 알림·기존 제안/계약 보존은 2-C 이후 해당 범위다. 이번에 임의 구현하지 않는다.

## 검증 재현

저장소 루트에서 `npm run test:web`, `npm run build:web`, `npm run format:check`, `npm run check:tokens`. 정식 브라우저는 `npm run test:web:e2e`이며 기존 Chromium/모바일 프로젝트·재시도0을 유지한다.

로컬 Edge 검증은 무시되는 `tmp/playwright.2b.config.ts`로 채널과 5183만 지정한다. 기존 개발 서버를 재사용하지 않는다. 시각 캡처/운영 smoke 재현과 실제 검증 수치는 `qa/frontend-2b/README.md`, 최종 상태·Git/원격 CI는 `frontend-progress.md`에 기록한다. 2-B 클라이언트/Mock 통합이며 2단계 전체 완료가 아니다.
