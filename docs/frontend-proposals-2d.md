## API 대조·미결정

- `api문서.txt` 676~774행: POST applications, 본인 공고 GET, 내 지원 GET, accept/decline. 실제 API/shared의 기존 정의는 수정하지 않는다. `accept`는 즉시 MATCHED·타후보 종료이므로 협의 요청에 연결하지 않는다. 철회·무선정·채팅은 API가 없다. 전부 DEV/MSW `/__mock__/proposals` 아래 가상 계약이며 운영 빌드에는 포함하지 않는다.
- D06: 캠페인당 유효 제안 1개는 제안이다. 중복 클릭은 같은 제출 ID로 멱등 처리한다. 거절/철회 후 재지원은 허용 여부를 정하지 않고 UI에 결정 대기로 표시하여 차단한다. Mock의 임시 보호 동작을 제품 정책으로 채택하지 않는다.
- D07: 수동 재조회·표시된 마지막 메시지까지 명시적 읽음은 예시다. 자동 polling/WebSocket·읽음/페이지/집계 계약은 미정이다. 글자수 4,000, 관련 작업물 최대20개, 양의 정수 견적·기간은 Mock 입력 보호 후보이며 확정 한도/금액 정책이 아니다. 인앱 알림 카운트를 채팅 읽음으로 변경하지 않는다.
- D19: 거절/철회/무선정으로 협의 자체가 종료될 때만 읽기 전용이다. 모집 마감·일반 대화 48시간으로 방을 닫지 않는다. 계약 후 완료/분쟁/보관/재개는 이번에 판정하지 않는다. 모델의 `contracted`는 향후 경계 검사와 합성 단위 fixture용이며 실제 계약 조회 증거가 아니다.
- D20: PC/모바일 작업·대화 배치는 제안 상태다. 현재 동일 페이지에서 협의 요약·대화·계약 전 안내를 제공한다. 최종 조건·서명·결제·제작 행동을 만들지 않는다.

## 데이터·오류 경계

- 단일 탭 모듈 메모리. 계정 전환 동안 같은 탭 데이터는 유지하되 Query 캐시·컴포넌트 입력은 epoch/계정/URL로 격리한다. 새로고침은 데이터 초기화이며 영구 저장/다중 탭 증거가 아니다.
- handler는 Bearer·ACTIVE·역할·소유자/당사자와 지연 후 epoch를 재검사한다. 다른 후보 목록/본문/대화를 반환하지 않는다. 관련 작업물은 본인 공개 ID/제목 사본만 전달하고 파일·외부 URL·비공개 설명은 전송하지 않는다. 실제 미디어 snapshot은 남는다.
- 변경 자동 재시도 없음. 제출·협의 요청·메시지 전송은 식별자 재사용으로 중복을 막는다. 거절/철회는 revision 확인 후 처리한다. 응답 유실·409는 최신 상태 재조회 후 판단한다. 메시지 재시도는 실패한 동일 ID/내용을 사용하며 종료/역할도 다시 검사한다. 페이지 이동 후 실패 입력 복원은 지원하지 않는다.
- 읽음은 메시지 배열 내 순서로 전진만 허용한다. 종료 방도 당사자의 기록 조회·읽음을 허용한다. 메시지의 동의 표현으로 서명·납품·승인·정산을 만들지 않는다.
