# 3-A 최종 조건서 작성·버전 관리

- `케미 기능명세서.xlsx` 기능명세 33행 TERMS-01, 36행 TERMS-03의 작성/버전 부분, 정책 P09 및 D08을 대조했다. 금액·규격/수량·범위·자료·납기·수정·사용권·취소 조건을 구조화하고 불완전 작성본도 저장한다.
- `frontend-plan.md` 3단계와 기술 스택 PDF의 기존 React/Vite·Router·Query·Axios·RHF/Zod·Workspaces 구성을 유지한다. 기존 KEMI 카드·공통 UI·단색 작업 화면·타이포·600/1024px 구간을 사용한다.
- `api문서.txt`, 현 API/shared에는 조건서·버전 API가 없다. 실제 경로/DTO를 추정하지 않고 **DEV/MSW `/__mock__/terms/:requestId`**로 분리한다. 기존 운영 `/workspace/:requestId`는 제안·협의 연결 준비 안내를 유지한다. 운영 Mock/worker 제외를 따로 검증한다.
- **3-A만 해당한다.** TERMS-02 확인/서명 요청·48시간 시작/만료·구버전 서명 보존/재확인·CONTRACT-01 양측 서명/선정·결제는 미구현이다. 저장한 작성본은 서명 대상 고정 버전이나 계약이 아니며 서명 요청 버튼은 후속 범위 안내로 비활성이다. TERMS-03 전체나 3단계 전체를 완료로 표시하지 않는다.

## 동작

1. 기존 공개 제안→협의 작업 공간에서 당사자만 조건서를 조회한다. 모집 마감은 유효 협의의 작성을 차단하지 않는다. 협의 종료 뒤에는 기록 조회만 허용한다.
2. 공고의 공개 필드·제안 견적/기간/방향·크리에이터의 현재 대표 **공개** 패키지를 참조 후보로 제공한다. 비공개 공고 참고 자료·개인 프로필·비공개 패키지는 전달하지 않는다. 제안 또는 패키지 값 불러오기는 사용자의 명시적 행동이며 기존 편집 내용이 있으면 차단한다. 입력 취소 행동으로 최신 저장본을 다시 불러올 수 있다.
3. 첫 저장 때 참조 사본을 고정한다. 원본과 최종 값은 별도이며 저장 후 원본의 가격/공개 상태 변경은 저장 이력을 덮어쓰지 않는다. 기존 사본은 기존 당사자의 증빙으로 남는다. 첫 저장 전에 참조가 바뀌면 409/재조회로 재검토한다. 공고 모집 기간을 작업 납기로 치환하지 않는다.
4. 저장은 순서가 있는 작성본을 추가한다. 이전 작성본의 값·저장자·한국 시간·참조 사본을 보존한다. 선택 이력과 바로 전 작성본의 변경 전/후 값을 조회한다. 과거 값을 편집기에 불러온 후 저장해도 새 작성본이며 기존 이력을 수정하지 않는다.
5. 필수 항목 누락은 저장 이력에 표시하고, 금액 형식/과대 입력은 필드 오류로 연결한다. 작성본 저장과 최종 확인/서명 요청을 분리한다.

## Mock 가정·미결정

- **D08 유지:** 양 당사자 편집·revision 비교·명시적 기준 갱신은 충돌 검증용 Mock 예시다. 최종 작성 권한/동시 편집/서명 입력/정확한 만료 경계는 확정하지 않는다. 첫 저장 때 현재 대표 공개 패키지를 참조하는 방식도 Mock 후보이며 최종 패키지 선택 계약은 협의가 필요하다.
- 문자열 4,000자·양의 안전한 정수 금액은 입력 보호 후보이며 승인된 제품 정책/최종 금액·세금 규칙이 아니다. 납기는 시작 기준을 포함한 텍스트이며 날짜 계산/제작 시작을 생성하지 않는다.
- 새 저장마다 불변 작성본을 남기는 방식은 로컬 이력 예시다. 서명 요청된 버전의 불변성은 후속 서명 모델에서 추가 검증해야 한다. 서명 데이터/계약 상태를 임의 생성하지 않는다.
- 현재 공개 제안 협의방을 이용한다. 캠페인 없는 직접 의뢰 생성/3단계 전체 통합·PC/모바일 작업/대화 탭 D20 확정은 후속 범위다.

## 오류·권한·검증 경계

- GET/POST는 Bearer·ACTIVE·당사자/역할/방 존재를 검사한다. 지연 뒤 epoch·최신 협의 상태를 재검사해 계정 변경/종료 뒤 저장을 차단한다. 종료 방의 당사자 읽기는 유지한다. 실제 서버 보안/DB 권한 검증의 대체물이 아니다.
- 계정/epoch/방별 Query와 컴포넌트 입력을 분리한다. 조회 취소·자동 재시도 금지·unknown/Zod 응답 검사를 유지한다. 재조회는 편집 내용을 덮어쓰지 않는다. revision 충돌 시 최신 버전 비교와 명시적 기준 갱신 후 새 저장을 허용한다.
- 응답 유실/결과 불명확 때 편집을 잠그고 같은 요청 ID/내용으로 수동 재시도하거나 최신 이력에서 해당 ID를 확인한다. 성공 응답 후 재조회도 실패하면 완료로 표시하지 않는다. 중복 요청/같은 값은 추가 버전을 만들지 않는다.
- 모든 데이터는 단일 탭 메모리이며 새로고침하면 초기화된다. 실제 API/DB·다중 탭·알림·영구 저장·서명·외부 제공자 검증은 없다.
- 공식 구현 참고: [RHF useForm](https://react-hook-form.com/docs/useform), [TanStack Query cancellation](https://tanstack.com/query/latest/docs/framework/react/guides/query-cancellation). 신규 의존성/버전 변경은 없다.
