# #73·#74·#76의 실제 API 이관과 정리 기준

2026-10-27. 기준은 #73 `82fb72f`, #74 `eaca8ec`, #76 `0c9e2f2`와 #78의 실제 API 구현이다. 세 PR은 순서대로 쌓인 개발 Mock 구현이므로 전체 diff를 다시 병합하지 않고 기능·권한·실패 시나리오를 대조했다. #77까지 병합된 코드와 기존 Mock 작업은 보존한다.

## #73: 내 활동·저장·추천

- `ActivityLive.tsx`와 `GET /api/activity`가 본인의 모집·요청·계약을 연결한다. 이번 보완으로 임시저장 초안을 조회하고 이어 쓰며 거래 단계 필터를 URL에 유지한다. 열린 분쟁은 별도 단계이며, 정산 없는 제작 완료 표시는 정산 대기로 안내한다. 납품·정산·리뷰로 이동할 수 있다.
- `ProjectDraftEditorLive.tsx`가 기존 초안 API를 사용해 부분 저장·복원·수정·공개한다. 모집 기간은 기존 API의 3·7·14일 기준이다. 공개 실패 뒤 같은 초안을 수정하므로 새 초안을 계속 만들지 않는다. 기존 공개 모집 수정은 유지한다.
- 저장 목록은 종료 상태를 표시하고, 삭제된 공고는 제목·본문을 숨긴 ID만 제공하여 저장 해제를 허용한다. 페이지와 수동 재조회가 있다.
- 추천은 기존 서버 규칙(프로필/저장한 목적·스타일, 없으면 최신)을 유지한다. 서버가 정보 부족·일치·일치 없음의 근거를 제공하고 화면에 적합 보장이 아님을 안내한다. Mock의 간소한 분야 일치 규칙으로 실제 규칙을 덮어쓰지 않는다.

## #74: 알림·리뷰

- `NotificationsLive.tsx`가 실제 DB 알림을 20개씩 조회한다. 페이지와 미확인 필터를 URL에 보존하며 개별·선택·전체 읽음, 수동 재조회, 조회 실패 시 이전 목록 숨김을 제공한다. 읽음으로 마지막 페이지가 사라지면 유효한 페이지로 이동한다. 인앱 미확인 수와 채팅 미확인 수는 별개다.
- 기존 실제 거래 API의 성공 알림과 읽음 저장을 사용한다. 개발 Mock의 메모리 이벤트/ID를 실제 API에 전송하지 않는다.
- `SettlementLive.tsx`와 리뷰 API에 선택 태그(최대 5개·각 30자), 본문 최대 2,000자, 응답 유실 뒤 상태 재조회와 동일 내용 재전송 처리를 추가한다. 동일 내용은 같은 리뷰를 반환하고 알림을 추가하지 않으며 다른 내용은 409다. 최종 수령 완료와 `SIMULATED` 정산 성공을 모두 확인해야 리뷰할 수 있다.
- **공개 기준은 사용자의 명시적 선택에 따라 기존 실제 API를 유지한다.** 받은 리뷰 공개 목록·상대방 알림을 유지하며, Mock의 본인만 보기 정책을 가져오지 않는다. 리뷰 수정·삭제·취소 거래 리뷰의 새 정책을 추가하지 않는다.

## #76: 신고·제한·행동 기록

- #78의 `SafetyLive.tsx`, 신고/운영 API, DB 조치 이력이 신고·수동 검토/경고/제한/해제·당사자 안내·이의를 대체한다. 신고만으로 자동 제한하지 않는다. 여러 신고의 제한은 독립적이며 신규 거래를 제한해도 기존 거래 접근은 유지한다.
- 신고자는 상대방의 이의 내용을 볼 수 없다. 최근 안내 50개 밖의 제한도 유효하다. 계정 전환 후 늦은 응답은 인증 경계에서 취소한다.
- 행동 기록은 허용된 이름·대상 ID·시각만 전송한다. 피드/제작자는 조회 성공, 영상은 `playing`, 의뢰/계약/정상 정산은 성공 상태를 기준으로 한다. 실패는 거래를 막지 않고 세션 전환 시 대기 기록을 버린다. 취소 완료를 정상 정산 성공으로 세지 않는다.
- Mock은 브라우저 메모리, 실제 구현은 서버 DB를 사용한다는 차이가 있다. D18·D21·D22의 운영 권한·동의·보존 정책이 확정됐다는 의미는 아니다.
