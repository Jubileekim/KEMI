# 4-D 승인·최종 파일·수령

## 근거와 범위

기능명세서 기능 DEL-03/04/05(47~49행), FILE-01 일부, WORK-03/04 일부와 P13/P15/P16/P22를 적용한다. 계획 §4단계 3·4항 중 수령까지이며 SETTLE-01은 제외한다. 기술 PDF와 기존 npm Workspaces/React·Query·Axios·Zod·MSW를 유지하고 API/shared·의존성·디자인 토큰은 변경하지 않는다. API 문서/실제 API/shared에 대응 계약이 없어 `/__mock__/deliveries` 안의 DEV/MSW 계약으로만 제공한다.

## 구현 계획과 완료 기준

1. `final-model.ts`와 delivery 모델/핸들러: 특정 최신 완성 검토본 승인, 승인 버전과 계약 파일 묶음 연결, 전용 수령/문제 기록. 단위 검사에서 권한·초안/구버전/열린 요청·보류·같은 ID/내용 충돌·원자적 기록을 확인한다.
2. `ReviewActions.tsx`, `FinalReceiptPanel.tsx`, `FinalPanelMock.tsx`와 delivery 화면/API: 승인 확인, 파일별 종류/설명/다운로드, 계약 원문 확인, 명시적 수령과 문제 신고를 분리한다. 응답 유실 시 새 명령 차단·재조회·같은 ID 재전송, 조회 오류 시 파일 숨김. 브라우저에서 정상 공개 제안→서명/결제/준비/검토→승인→최종 ZIP 전달→다운로드→수령을 확인한다.
3. 같은 방의 확정 사건 안내·정확한 버전/전달 URL, 권한·실패/지연·새로고침·모바일 및 기존 4-B/4-C 회귀와 운영 DEV 제외를 검사하고 기록/커밋/푸시/Draft PR로 전달한다.

## 실패 대비·미결정

- 초안/초안 수정본·구버전 승인 차단. D11 요청 중 승인 정책은 미결정이므로 열린 요청 때 보류하는 개발 예시다. 승인 후 새 검토/수정과 재승인/파일 재전달은 별도 협의 전 잠그는 Mock 보호이며 서비스 정책 확정이 아니다.
- 파일 불일치/손상/워터마크 잔존/미해결 분쟁은 문제 신고로 보류한다. 자동 해제/교체/운영 판정은 D11/D13/API 조율 후다. 수령은 정산의 선행 기록일 뿐이며 실제 정산 조건 판정·정산 실행·완료는 미구현이다. 준비 문제 또는 결과 확인 중에는 수령을 허용하지 않는다.
- 깨끗한 최종본, 합의한 촬영원본/편집 프로젝트/현재 작업본을 구분한다. 서명 규격/범위/원본 조건은 원문을 보여주고 제작자·의뢰인 확인을 받는다. 텍스트 자동 해석/내용·워터마크·악성 파일·ZIP 내부 검사로 오인하지 않는다.
- ZIP 허용은 P15 확정. MP4/WebM/ZIP, 파일당300MiB·최대20개·설명2000자는 개발 입력 보호일 뿐 D17 형식/단위/개수/검사/보존은 미결정이다. 대용량/실제 저장·외부 제공자/영구 복원·다중 탭·서버 권한은 이번 검증에서 제외하고 미검증으로 남긴다.
- 같은 명령은 actor/내용 fingerprint 확인 후 무해 재전송한다. await 본문 뒤 계약/epoch/최신 state를 재검사한다. 파일 GET도 계약 당사자 확인, no-store, 임의 외부 URL 미사용. 실패/업로드만으로 시스템 안내를 만들지 않는다.
- 단일 탭 메모리이며 새로고침은 전체 Mock 초기화다. 무응답 자동 승인·다운로드/대화에 의한 수령/정산은 없다. 4단계 전체는 정산 등이 남아 미완료이며 단계 전체 완료 검증을 주장하지 않는다.
