# 01. Executive Summary

## 1.1 프로젝트 배경

개인은 일상과 인생의 중요한 순간을 영상으로 기록하고 공유한다.

결혼식, 돌잔치, 프로포즈, 가족 기념일과 같은 특별한 이벤트뿐 아니라 여행, OOTD, 브이로그, 챌린지, SNS 콘텐츠 등 개인이 제작하고 싶은 영상의 목적은 다양하다.

그러나 원하는 결과물을 직접 제작하려면 편집 기술을 익히거나 편집 도구를 사용해야 한다. 외주 제작을 선택하더라도 적합한 제작자를 찾고, 포트폴리오와 가격을 비교하고, 제작 조건을 협의하는 과정을 거쳐야 한다.

현재 국내 시장에는 크몽, 숨고, 전문 행사영상 제작업체 등 다양한 대안이 존재한다.

따라서 KEMI의 과제는 영상 제작 수요 자체를 새롭게 만드는 것이 아니라, **개인이 소액의 영상 제작 서비스를 더욱 직관적이고 간편하게 구매할 수 있는 경험을 제공하는 것**이다.

## 1.2 서비스 정의

**KEMI는 개인이 만들고 싶은 영상의 목적과 스타일에 맞는 크리에이터를 발견하고, 가격과 제작 조건을 확인한 뒤, 간편하게 제작을 의뢰하고 결과물을 전달받는 개인 영상 제작 거래 플랫폼이다.**

고객은 전문 영상 제작 지식 없이도 원하는 영상의 샘플을 탐색하고, 예산과 일정에 맞는 제작 서비스를 선택할 수 있다.

크리에이터는 본인의 영상 작품과 제작 패키지를 등록하여, 자신의 편집 스타일을 선호하는 고객으로부터 제작 의뢰를 받는다.

초기에는 고객이 보유한 사진과 영상을 활용하는 **편집 중심 서비스**에 집중한다. 출장 촬영, 스튜디오 촬영, 복잡한 영상 기획과 대규모 제작 프로젝트는 초기 표준 상품에서 제외한다.

## 1.3 핵심 제품 가설

> "영상 편집자를 구하고 싶다"가 아니라 "이런 영상을 만들고 싶다"에서 구매가 시작되면 개인 고객의 영상 제작 의뢰가 더 쉽고 빨라질 수 있다.

이를 위해 KEMI는 제작자의 프로필보다 **완성된 영상 작품과 구매 가능한 제작 패키지**를 중심으로 서비스 탐색 경험을 설계한다.

# 02. 시장 분석 및 기회

## 2.1 시장조사 결과

1차 국내 공개시장 조사에서 개인 영상 제작 서비스의 실제 판매와 구매 후기가 확인되었다.

특히 결혼식 식전영상, 돌잔치 성장영상, 가족 기념영상은 전문 제작업체와 프리랜서 마켓플레이스에서 지속적으로 제공되는 상품이다.

영상 편집 시장의 공개 견적 데이터 역시 존재하나, 기업과 개인 수요가 혼합되어 있어 전체 시장 규모나 B2C 구매량을 직접 산정하는 근거로 사용할 수 없다.

### 시장조사 핵심 발견

- 행사·기념일 영상은 실제 거래 시장이 존재한다.
- 저가형 템플릿 영상부터 고가 맞춤형 영상까지 가격대가 다양하다.
- 다수의 서비스는 기본 제작 가격을 공개한다.
- 실제 최종 가격은 원본 분량, 수정 횟수, 제작 기간 및 추가 옵션에 따라 달라질 수 있다.
- 사진 선별, 원하는 스타일 탐색, 제작 조건 이해, 일정 관리 등의 불편 사례가 확인되었다.
- 일상형 개인 SNS 영상의 반복 유료 구매 규모는 아직 확인되지 않았다.

## 2.3 시장의 구조적 특징

**① 기본가격은 상당수 공개되어 있다.**

따라서 '가격을 알 수 없는 폐쇄적인 시장'으로 규정하는 것은 적절하지 않다.

**② 최종 거래 조건은 표준화 수준이 다르다.**

영상 길이, 사진 수, 수정 범위, 음악 변경, 추가 옵션 및 납기에 따라 고객이 실제로 지불할 금액이 달라질 수 있다.

**③ 고객이 탐색하는 대상은 전문가이지만, 구매하려는 대상은 특정 영상 결과물이다.**

제작자의 경력보다 마음에 드는 완성 영상의 스타일이 구매 판단의 출발점이 될 가능성이 있다.

**④ 시장에 판매자가 존재한다는 사실과 신규 플랫폼의 필요성은 별개의 문제다.**

KEMI는 기존 서비스보다 편리한 탐색, 비교 및 거래 경험을 제공할 수 있어야 한다.

## 2.4 초기 시장 선정

**Primary Market: 개인의 인생 이벤트 및 기념일 영상**

- 웨딩 식전영상 및 모바일 초대영상
- 돌잔치 성장영상 및 초대영상
- 프로포즈 및 커플 기념영상
- 부모님 생신·환갑·칠순·감사영상

**Expansion Market: 개인의 일상 및 SNS 영상**

- 여행 하이라이트
- OOTD 및 패션 릴스
- 일상 브이로그
- 챌린지 및 트렌드 영상
- 꿀팁·정보형 쇼츠
- 졸업·송별·반려동물 등 개인 추억영상

초기 상품 구분은 고객의 구매 목적에 따라 설계한다. 현재 자료만으로 카테고리별 국내 실제 주문량 순위를 확정하지 않는다.

> "내가 찍어둔 사진과 영상을 활용해서 마음에 드는 기념 영상을 만들고 싶다. 복잡한 편집을 직접 하지 않고, 가격과 완성일이 확실한 곳에서 간단히 주문하고 싶다."

**핵심 불편 가설**

- 원하는 스타일의 영상을 제작하는 사람을 찾는 과정이 번거롭다.
- 샘플을 발견해도 최종 비용을 바로 확인하기 어렵다.
- 수십 장의 사진을 직접 고르고 정리해야 한다.
- 중요한 날짜에 맞춰 제작이 완료될지 걱정된다.
- 어떤 수정까지 포함되는지 이해하기 어렵다.

이 페르소나의 나이·예산·행동 특성은 제품 설계를 위한 가정이며, 실제 설문으로 확인된 대표 고객 특성이 아니다.

# 04. 문제 정의

## 4.1 핵심 고객 문제

### P1. 원하는 영상과 제작자를 찾는 과정의 불편

고객은 결혼식·돌잔치·가족 기념일 등 구체적인 사용 목적을 갖고 있지만, 원하는 결과물의 분위기를 설명하거나 제작자를 비교하는 데 어려움을 겪을 수 있다.

**해결 방향:** 용도별 영상 분류, 작품 중심 탐색, 샘플 영상 미리보기.

### P2. 최종 가격과 제작 조건의 불확실성

기본 가격이 공개되어 있더라도 제작 분량, 수정 범위, 추가 옵션 및 납기에 따라 최종 비용이 달라질 수 있다.

**해결 방향:** 기본 제작 패키지와 선택 가능한 추가 옵션, 확정 전 총액 표시.

### P3. 제작 자료 준비의 번거로움

고객은 영상 제작을 위해 사진·영상·문구·음악을 준비해야 한다. 특히 행사형 영상에서는 자료 선별 자체가 부담일 수 있다.

**해결 방향:** 목적별 의뢰 폼, 원본 업로드, 필수 자료 안내, 선택적인 자료 선별 서비스.

### P4. 제작 일정과 수정 과정의 불확실성

행사 날짜가 정해진 고객에게는 제작 지연이 큰 위험이다. 수정 요청이 어느 범위까지 가능한지도 명확해야 한다.

**해결 방향:** 제작 가능일 및 납기 확인, 진행 상태 표시, 표준 수정 정책.

### P5. 소액 영상 제작에 비해 복잡할 수 있는 거래 과정

짧은 영상 하나를 주문하더라도 여러 차례 문의와 조건 협의가 필요할 수 있다.

**해결 방향:** 정형화된 패키지와 제작 의뢰 프로세스.

## 4.2 핵심 문제 정의 문장

**"개인은 자신이 원하는 영상의 모습은 알고 있지만, 그 영상을 적절한 가격과 일정으로 제작해 줄 사람을 쉽고 빠르게 찾고 의뢰하기 어려울 수 있다."**

KEMI는 이 문제를 작품 중심 발견과 표준화된 소액 영상 거래 경험으로 해결한다.

# 05. 제품 비전 및 포지셔닝

## 5.1 제품 비전

**누구나 만들고 싶은 영상을, 자신에게 맞는 크리에이터와 쉽고 빠르게 완성하는 세상.**

KEMI는 전문적인 영상 제작 지식이 없는 사람도 자신의 아이디어와 원본 자료만으로 만족스러운 결과물을 얻을 수 있는 환경을 지향한다.

## 5.2 브랜드 메시지

**Great Chemistry Makes Great Content**

> 내가 원하는 순간과 크리에이터의 감각이 만나, 나만의 영상이 완성된다.

## 5.3 포지셔닝

**개인을 위한 작품 중심의 마이크로 영상 제작 마켓플레이스**

| 비교 영역   | 일반 외주 거래 방식      | KEMI 목표 경험             |
| ----------- | ------------------------ | -------------------------- |
| 탐색 시작점 | 전문가·서비스 검색       | 원하는 영상 작품 발견      |
| 상품 분류   | 편집 기술·제작 서비스    | 사용 목적·스타일           |
| 가격 확인   | 패키지 또는 개별 견적    | 포함 조건과 최종 금액 명시 |
| 의뢰 과정   | 요구사항 전달·협의       | 표준화된 간편 주문         |
| 자료 전달   | 판매자별 개별 방식       | 통합 업로드                |
| 진행 상태   | 채팅·외부 채널 확인 가능 | 플랫폼에서 단계별 조회     |
| 거래 완료   | 플랫폼·업체별 절차       | 납품·승인·리뷰 연계        |

위 비교는 KEMI의 목표 경험을 정의한 것이며, 모든 기존 서비스가 오른쪽 기능을 제공하지 않는다는 의미는 아니다.

## 5.4 차별화의 핵심

**영상 제작자를 검색하는 플랫폼이 아니라, 만들고 싶은 영상을 발견하고 주문하는 플랫폼.**

AI 기능의 수나 제작자 데이터베이스 규모보다 고객이 실제로 구매를 완료하는 경험의 단순성을 핵심 경쟁력으로 설정한다.

# 06. 서비스 구조

## 6.1 플랫폼 이용자

KEMI는 두 가지 주요 사용자 역할로 구성된다.

**CLIENT — 의뢰인**

- 영상 작품 탐색
- 제작 패키지 선택
- 직접 의뢰 및 맞춤 의뢰
- 제작 자료 업로드
- 가격·조건 합의
- 계약·결제·납품 확인
- 리뷰 작성

**CREATOR — 크리에이터**

- 크리에이터 프로필 관리
- 포트폴리오 등록
- 제작 패키지 등록
- 직접 의뢰 수신
- 공개 맞춤 의뢰 지원
- 조건 확인·합의
- 계약·납품·수정
- 리뷰 및 정산 내역 확인

기존 시스템의 `CLIENT`, `CREATOR` 역할 코드는 유지한다. 사용자 화면에서는 `의뢰인`, `크리에이터`로 표시한다.

## 6.2 핵심 콘텐츠 구조

### ① 영상 작품 (Portfolio Work)

실제 제작 스타일을 보여주는 샘플 영상이다.

필요 정보:

- 작품 제목
- 영상 미리보기 또는 썸네일
- 사용 목적
- 스타일 태그
- 영상 길이
- 제작 크리에이터
- 연결된 제작 패키지

### ② 제작 패키지 (Service Package)

크리에이터가 제공하는 구매 가능한 영상 제작 상품이다.

필요 정보:

- 패키지명
- 기본 제작비
- 제공 영상 수
- 최종 영상 길이
- 원본 자료 허용 범위
- 포함 편집 요소
- 예상 제작 기간
- 기본 수정 횟수
- 추가 옵션과 비용
- 납품 형식
- 작업 가능 여부

### ③ 영상 제작 의뢰 (Work Request)

고객이 실제 제작을 요청한 거래 단위다.

필요 정보:

- 의뢰인·크리에이터
- 선택 패키지 또는 프로젝트
- 제작 목적
- 원하는 스타일
- 원본 자료
- 요청 문구
- 일정
- 가격·조건
- 거래 진행 상태

### ④ 공개 맞춤 의뢰 (Open Project)

정형화된 제작 패키지로 해결하기 어려운 요청이다.

고객이 원하는 영상의 목적과 조건을 등록하면 크리에이터들이 지원할 수 있다.

**운영 원칙**

표준 상품을 선택한 직접 의뢰와 공개 맞춤 의뢰는 시작 경로가 다르지만, 조건 합의 이후 공통 계약·결제·납품 흐름으로 연결한다.

# 07. 카테고리 및 상품 구성

## 7.1 초기 영상 카테고리

| 1차 카테고리 | 하위 카테고리                             |
| ------------ | ----------------------------------------- |
| 웨딩·커플    | 식전영상, 영상 청첩장, 프로포즈, 기념일   |
| 아이·가족    | 돌잔치 성장영상, 백일, 생일, 가족 추억    |
| 감사·축하    | 부모님 감사, 환갑·칠순, 퇴임, 축하 메시지 |
| 여행·일상    | 여행 하이라이트, 브이로그, 추억 영상      |
| SNS·숏폼     | 릴스, 쇼츠, OOTD, 챌린지, 꿀팁 영상       |

첫 세 카테고리는 초기 상품 운영의 우선 대상이다.

여행·일상 및 SNS 카테고리는 탐색 가능하도록 설계하되, 실제 유료 구매 수요가 충분히 검증되기 전에는 상품 공급을 제한적으로 운영할 수 있다.

## 7.2 탐색 필터

- 영상 제작 목적
- 영상 스타일
- 예상 예산
- 최종 영상 길이
- 제작 소요일
- 크리에이터 작업 가능 여부

영상 스타일 태그는 감성적인, 유쾌한, 시네마틱, 깔끔한, 트렌디한, 레트로 등으로 시작하되 팀 검토 후 공통 분류값을 확정한다.

**분류 설계 원칙:** `영상 목적`과 `영상 스타일`은 서로 다른 속성으로 저장한다. 예를 들어 돌잔치 영상도 감성형·코믹형·시네마틱형으로 제작할 수 있기 때문이다.

## 7.3 초기 제작 패키지 가설

아래 표는 시장조사를 기반으로 작성한 **표준 상품 기획 예시**다. 확정 판매가나 공급자가 동의한 제작 조건은 아니다.

| 항목           | BASIC              | STANDARD       | PREMIUM          |
| -------------- | ------------------ | -------------- | ---------------- |
| 예시 가격      | 15,000원           | 29,000원       | 49,000원         |
| 제작 유형      | 간단한 템플릿 편집 | 기본 맞춤 편집 | 확장 맞춤 편집   |
| 영상 길이      | 15~30초            | 30~60초        | 60~90초          |
| 사진·영상 자료 | 소량               | 중간 분량      | 비교적 많은 분량 |
| 기본 수정      | 1회                | 1회            | 2회              |
| 납기 가설      | 3영업일            | 3영업일        | 5영업일          |
| 적용 범위      | 짧은 초대장·릴스   | 기념영상·숏폼  | 가족·행사형 영상 |

**실제 서비스 정책**

- 플랫폼이 모든 제작자에게 동일한 가격을 강제하지 않는다.
- 패키지별 가격과 포함 범위는 제작자가 등록하고, 플랫폼은 이를 비교 가능한 구조로 표시한다.
- 가격대별 필터를 제공하되 실제 총액과 일치하지 않는 최저가 표시는 지양한다.
- 제작 범위를 초과하는 요청은 별도 맞춤 견적 대상으로 전환한다.
- 급행 옵션은 제작자의 수락 및 일정 확인이 있어야 확정된다.

## 7.4 초기 서비스 제외 범위

- 출장 영상 촬영
- 전문 카메라 장비 및 촬영 인력 중개
- 장편 다큐멘터리 제작
- 복잡한 3D·VFX 작업
- 저작권 처리가 불명확한 외부 영상의 무단 편집
- 동의 없는 인물 이미지 합성·음성 복제

이 기능들은 초기 소액 편집 상품의 제공 범위에서 제외하고 향후 별도 서비스로 검토한다.

# 08. 핵심 사용자 시나리오

## 8.1 Scenario A — 제작 패키지 직접 의뢰

**대표 시나리오: 돌잔치 성장영상 의뢰**

1. 사용자가 KEMI 홈에 접속한다.
2. '돌잔치·성장영상' 카테고리를 선택한다.
3. 영상 작품 목록을 탐색한다.
4. 마음에 드는 작품을 선택하여 미리보기한다.
5. 해당 크리에이터의 제작 패키지를 확인한다.
6. 가격, 영상 길이, 납기 및 수정 조건을 비교한다.
7. '이 스타일로 의뢰하기'를 선택한다.
8. 로그인하지 않은 경우 회원가입 또는 로그인을 진행한다.
9. 의뢰 목적, 행사 예정일, 원하는 문구를 입력한다.
10. 필요한 사진과 영상 원본을 업로드한다.
11. 선택 옵션과 예상 최종 금액을 확인한다.
12. 제작 의뢰를 제출한다.
13. 크리에이터가 작업 가능 여부와 조건을 확인한다.
14. 변경 사항이 있으면 양측이 최종 조건에 합의한다.
15. 합의된 조건으로 계약서를 생성한다.
16. 양측이 계약서에 서명한다.
17. 의뢰인이 PG 테스트 환경에서 결제한다.
18. 크리에이터가 제작을 진행하고 결과물을 제출한다.
19. 의뢰인이 영상을 확인하고 승인하거나 수정 요청한다.
20. 최종 승인 후 모의 정산 및 리뷰 단계로 이동한다.

**UX 핵심 목표**

고객이 영상을 발견하고 제작 의뢰서를 제출하기까지의 과정은 최대한 짧고 명확하게 구성한다.

단, '간편 주문'은 제작자의 무조건적인 자동 수락이나 즉시 계약 체결을 의미하지 않는다. 납기·조건이 실제로 확정되는 시점은 제작자 수락 및 합의 이후다.

## 8.2 Scenario B — 공개 맞춤 의뢰

**대표 시나리오: 특별한 프로포즈 영상 제작**

1. 의뢰인이 '원하는 영상 직접 요청하기'를 선택한다.
2. 제작 목적, 원하는 스타일, 영상 길이, 예산, 희망 납기를 입력한다.
3. 참고 영상을 첨부하거나 설명한다.
4. 필요하면 AI 단가 분석을 통해 예상 제작비를 확인한다.
5. 공개 프로젝트를 등록한다.
6. 관련 크리에이터들이 프로젝트를 탐색하고 지원한다.
7. 의뢰인이 지원자의 포트폴리오와 조건을 비교한다.
8. 의뢰인이 한 명을 선정한다.
9. 최종 금액 및 납품 조건에 합의한다.
10. 계약서 생성·서명 및 테스트 결제를 진행한다.
11. 크리에이터가 제작·납품한다.
12. 의뢰인이 승인하고 모의 정산 및 리뷰를 완료한다.

공개 프로젝트가 계약 확정 상태가 되면 신규 지원은 중단하고, 기존 미선정 지원자의 상태는 기존 RFP·백엔드 정책에 따라 처리한다.

## 8.3 Scenario C — 일상 SNS 영상 의뢰

**대표 시나리오: 여행 릴스 제작**

1. 사용자가 SNS·숏폼 카테고리에서 '감성 여행 릴스'를 발견한다.
2. 마음에 드는 30초 샘플을 확인한다.
3. 제작비와 납기를 확인한다.
4. 여행 중 촬영한 원본 영상들을 첨부한다.
5. 원하는 음악 분위기와 자막 스타일을 선택한다.
6. 제작 의뢰를 제출한다.
7. 제작자가 조건에 동의하면 공통 거래 단계로 이동한다.
8. 완성된 세로형 영상을 받아 개인 SNS에 게시한다.

해당 시나리오는 제품 확장 방향을 보여주기 위한 것으로, 초기 유료 구매 수요가 검증되었다고 간주하지 않는다.

# 09. 핵심 기능 요구사항 및 우선순위

## 9.1 범위 구분

기능 우선순위는 다음 기준으로 관리한다.

- **P0-R:** 코드잇 RFP 충족에 필요한 필수 기능
- **P0-U:** KEMI의 B2C 핵심 사용자 경험
- **P1:** 서비스 완성도를 높이는 후속 기능
- **P2:** 실제 운영·확장 단계 기능

P0-R은 기존 사용자 제공 PRD에 명시된 RFP 요구사항을 기준으로 정리한다. 최종 개발 범위는 RFP 원문과 대조한다.

P0-U 중 신규 개발이 필요한 기능은 실제 구현 일정을 검토하여 필수 기능을 지연시키지 않도록 한다.

# 10. 서비스 운영 정책

## 10.1 가격 정책

**핵심 원칙: 고객은 결제 전에 확정된 제작 금액과 포함 범위를 확인할 수 있어야 한다.**

| 항목               | 정책 방향                    | 상태               |
| ------------------ | ---------------------------- | ------------------ |
| 기본 가격          | 크리에이터가 패키지별 등록   | 채택 방향          |
| 목표 가격대        | 초기 기본 상품 1만~5만 원    | 사업 가설          |
| 추가 옵션          | 사전에 정의한 금액을 명시    | 채택 방향          |
| 맞춤 의뢰          | 개별 금액 합의               | 채택 방향          |
| 수수료             | 계약금액의 10% 차감          | RFP 모의 정산 기준 |
| 구매자 추가 수수료 | MVP에서 별도로 부과하지 않음 | 초기 정책안        |
| 가격 변경          | 양측 합의 필요               | 필수               |
| 최종 금액          | 계약에 기록된 합의 금액      | 필수               |

10%는 교육 프로젝트의 모의 정산 기준이다. 실제 상용 운영의 수수료율은 결제비용·운영비·공급자 수익성 검토 이후 별도 확정한다.

## 10.2 제작 의뢰 및 수락

- 의뢰인은 패키지를 선택해 요청서를 제출한다.
- 제출된 요청은 크리에이터에게 전달된다.
- 제작자가 일정과 조건을 수락하기 전에는 납기 확정으로 표시하지 않는다.
- 제작자가 거절하면 고객에게 안내한다.
- 제작 범위가 변경되면 수정된 금액과 납기를 제안할 수 있다.
- 계약 이후의 변경은 별도의 계약 변경 또는 종료 정책을 따른다.

직접 의뢰의 응답 유효기간은 기본 48시간을 검토하되 팀의 기존 백엔드 정책과 정합성을 확인한다.

## 10.3 영상 수정

**표준 상품 정책안**

- 기본 수정은 패키지별 1~2회 제공한다.
- 자막 오탈자, 가벼운 컷 조정, 기존 제작 브리프 충족을 위한 보완은 기본 수정 범위로 본다.
- 새로운 콘셉트, 전체 영상 재구성, 계약에 없던 분량 추가는 별도 협의 대상으로 본다.
- 수정 요청 시 내용과 이력을 거래 내역에 보존한다.

## 10.4 납품

- 최종 납기는 계약 조건으로 확정한다.
- 제작자는 파일 업로드를 통해 결과물을 제출한다.
- 의뢰인은 납품물을 확인하고 승인하거나 수정 요청한다.
- 승인 전에는 정상 완료로 정산하지 않는다.
- 반복 수정 또는 분쟁 상황은 별도의 상태로 관리한다.

## 10.5 취소·환불

| 상황            | 처리 방향                           |
| --------------- | ----------------------------------- |
| 제작자 수락 전  | 의뢰 철회 가능                      |
| 계약 체결 전    | 미합의 또는 거절로 종료 가능        |
| 계약 후·제작 전 | 별도 계약 취소 절차                 |
| 제작 진행 중    | 작업 진행도와 합의 조건에 따라 처리 |
| 결제 실패       | 결제 완료로 표시하지 않음           |
| 환불 요청       | 취소와 환불 상태를 분리             |
| 납품 불일치     | 수정 또는 분쟁 처리                 |

상용화 전에는 전자상거래·용역계약·소비자보호 관련 법적 요구사항을 검토해 실제 취소·환불 정책을 확정해야 한다.

## 10.6 저작권 및 초상권

영상 제작 서비스 특성상 개인의 사진과 영상에 대한 보호가 중요하다.

- 고객은 의뢰 자료를 사용할 권한이 있어야 한다.
- 미성년자가 등장하는 자료는 보호자의 적절한 동의와 제공 권한을 확인하도록 한다.
- 의뢰인의 원본은 기본적으로 비공개 처리한다.
- 계약 내용에 저작물의 사용 목적과 이용 범위를 명시한다.
- 포트폴리오 재공개는 의뢰인의 명시적 동의를 받아야 한다.
- 외부 음원·폰트·이미지는 적절한 사용 권한이 있는 자료만 허용한다.
- 동의 없는 얼굴 합성, 사칭 영상 및 음성 복제는 허용하지 않는다.
- AI 합성 기능 도입 시 별도의 동의·권리 검증 절차를 설계한다.

## 10.7 개인정보 및 파일 보관

고객이 제공하는 가족사진, 어린이 사진, 사적인 영상은 민감한 개인 콘텐츠로 취급한다.

- 원본 파일의 접근은 거래 당사자와 승인된 운영 범위로 제한한다.
- 공개 작품과 개인 주문 원본을 분리한다.
- 다운로드 링크에는 접근 권한과 유효기간을 적용한다.
- 서비스 목적 외의 2차 이용을 금지한다.
- 보관 기간, 삭제 요청, 계약 증빙의 보존 범위는 별도 개인정보 처리 정책에서 확정한다.

4. **불필요한 입력 최소화:** 패키지에 이미 정의된 내용을 다시 입력하게 하지 않는다.
5. **단계 명확성:** 의뢰 접수, 제작자 수락, 계약, 결제, 제작, 납품을 구분한다.
6. **신뢰 확보:** 실제로 확정되지 않은 일정이나 결제 상태를 확정된 것처럼 표현하지 않는다.
7. **접근성:** 영상 썸네일 외에도 제목·가격·설명 등의 텍스트 정보를 제공한다.

# 12. 거래 상태 및 예외 처리

## 12.1 일반 거래 상태

고객에게 표시되는 대표 단계는 다음과 같다.

**의뢰 접수 → 제작자 확인 → 조건 합의 → 계약 체결 → 결제 완료 → 제작 중 → 납품 확인 → 거래 완료**

각 단계에는 서버 상태와 다음에 수행할 행동이 대응되어야 한다.

실제 API의 상태 코드와 DB 상태값은 기존 `@kemi/shared` 및 ERD를 기준으로 구현하며, 화면의 사용자 친화적 문구와 구분한다.

## 12.2 주요 예외 처리

| 예외 상황               | 기대 동작                              |
| ----------------------- | -------------------------------------- |
| 중복 의뢰 제출          | 요청 식별키로 중복 생성 방지           |
| 같은 프로젝트 중복 지원 | 지원 차단 및 오류 안내                 |
| 모집 마감 이후 지원     | 서버에서 지원 차단                     |
| 제작자 의뢰 거절        | 의뢰인에게 결과 안내                   |
| 금액 합의 실패          | 미합의 상태로 종료                     |
| 두 명 이상 계약 시도    | 공개 프로젝트당 최종 계약 한 개만 허용 |
| 서명 도중 조건 변경     | 기존 서명 대상 무효 처리 및 재확인     |
| PG 결제 실패            | 미결제 상태 유지                       |
| PG 중복 콜백            | 결제 중복 반영 방지                    |
| 원본 업로드 실패        | 실패 파일 식별 및 재시도               |
| 납품 후 수정 요청       | 합의된 범위 내 수정·재납품             |
| 계약 취소               | 계약 취소와 환불 완료 상태 분리        |

## 12.3 계약 및 결제 원칙

- 계약서는 최종 합의 조건을 기준으로 생성한다.
- 계약 조건 변경 후에는 변경된 내용을 다시 확인해야 한다.
- 동일한 조건 버전에 양측이 서명해야 계약이 체결된다.
- PG 서버에서 결제 성공을 검증한다.
- 실제 결제금액과 계약금액의 일치 여부를 확인한다.
- 정산은 납품 승인 이후 수행한다.
- 기존 RFP의 10% 수수료 차감 모의 정산 로직을 유지한다.

# 13. 데이터 구조 및 개발 연계

## 13.1 기존 구조의 재사용

기존 ERD v0.6 및 백엔드 결정 기록의 다음 구조는 재사용 대상으로 유지한다.

- `users`
- `auth_identities`
- `auth_sessions`
- `auth_refresh_tokens`
- `client_profiles`
- `creator_profiles`
- `projects`
- `work_requests`
- `terms_versions`
- `contracts`
- 결제·환불·정산 관련 엔터티

이는 기존 설계의 재사용 방향이며, 모든 테이블과 기능이 현재 개발 완료되었다는 의미는 아니다.

## 13.2 B2C 전환에 필요한 주요 변경

### 의뢰인 프로필

기존 브랜드 중심 항목은 개인 고객에게 필수로 요구하지 않는다.

고객 화면에서는 개인 프로필 중심으로 정보를 수집하고, 브랜드명·업종 등 기존 선택 항목은 노출하지 않거나 후속 기업 고객 기능으로 분리한다.

기존 데이터베이스 컬럼을 즉시 삭제할 필요는 없다.

### 영상 분류 체계

기존 제품 산업군 중심 분류 대신 다음 두 축을 도입한다.

- **영상 목적:** 결혼식·돌잔치·프로포즈·가족·여행·SNS 등
- **영상 스타일:** 감성·코믹·시네마틱·트렌디 등

분류값은 프론트엔드·백엔드·DB 검증에서 일치해야 한다.

### 포트폴리오 및 제작 패키지

영상 작품과 판매 패키지를 구분한다.

하나의 패키지에 여러 샘플 작품이 연결될 수 있고, 하나의 작품이 관련 제작 패키지를 안내할 수 있다.

### 직접 의뢰

기존 `DIRECT_REQUEST` 구조를 확장해 특정 패키지 기반 의뢰를 표현한다.

공개 모집 기반 지원은 기존 `PROJECT_APPLICATION` 경로를 유지한다.

두 경로는 이후 조건 합의·계약·납품 구조를 공유한다.

## 13.3 확장 데이터 요구사항

ERD 다음 버전에서 검토할 항목은 다음과 같다.

| 데이터 개념           | 용도                         |
| --------------------- | ---------------------------- |
| 영상 목적·스타일 분류 | 카테고리 및 필터             |
| 포트폴리오 작품       | 샘플 영상과 썸네일           |
| 제작 패키지           | 가격·납기·작업 조건          |
| 패키지 옵션           | 추가 금액·수정 범위          |
| 요청 상세 자료        | 행사일·문구·원본 구성        |
| 파일 접근권한         | 비공개 업로드·다운로드       |
| 납품 버전             | 수정 전후 결과물             |
| 포트폴리오 공개 동의  | 고객 원본의 무단 재사용 방지 |

해당 구조는 신규 요구사항이며, 현재 스키마에 모두 구현되어 있다는 뜻이 아니다.

## 13.4 기존 확정 기술 스택

현재 팀의 백엔드 결정 기록과 저장소를 기준으로 다음을 유지한다.

| 영역            | 기술                                 |
| --------------- | ------------------------------------ |
| 프론트엔드      | React, Vite, TypeScript              |
| UI              | Tailwind CSS, shadcn/ui              |
| 백엔드          | Node.js, Express                     |

B2C 전환을 이유로 이 기술 스택을 변경하지 않는다.

# 14. 비기능 요구사항

## 14.1 보안 및 접근 제어

- 의뢰인은 본인의 비공개 요청·계약·결제·납품 정보만 조회할 수 있어야 한다.
- 크리에이터는 자신과 연결된 거래의 자료만 접근할 수 있어야 한다.
- 공개 포트폴리오와 비공개 고객 원본을 분리해야 한다.
- 인증된 사용자라도 다른 거래의 파일 다운로드 링크를 발급받을 수 없어야 한다.
- 개인정보와 인증 토큰은 로그에 노출되지 않아야 한다.

## 14.2 파일 업로드

기존 팀의 백엔드 결정 기록을 기준으로 다음 제한을 적용한다.

| 파일 종류 | 파일당 한도 | 허용 형식           |
| --------- | ----------- | ------------------- |
| 이미지    | 10MB        | JPG·JPEG, PNG, WebP |
| 영상      | 50MB        | MP4, MOV            |
| 압축파일  | 50MB        | ZIP                 |

다수의 모바일 원본 영상은 50MB를 초과할 수 있으므로, 초기 MVP는 허용 범위를 안내하고 이후 업로드 한도 확대 및 재개 가능한 업로드를 검토한다.

파일 업로드 완료 후에는 서버가 실제 파일의 크기·형식·접근권한을 확인해야 한다.

## 14.3 사용성

- 비회원은 공개 영상 작품을 탐색할 수 있다.
- 개인정보가 포함된 요청 제출과 거래는 인증 이후 진행한다.
- 의뢰서 제출 전 가격·납기·수정 범위를 확인할 수 있다.
- 업로드 실패·결제 실패·의뢰 거절 시 다음 행동을 안내한다.
- 모바일 화면에서 주요 버튼과 입력 항목이 정상 동작해야 한다.

## 14.4 시스템 신뢰성

- 계약 및 결제 중복 처리를 방지한다.
- 이미 마감된 공개 요청에 대한 지원을 차단한다.
- 거래 상태 변경은 서버에서 검증한다.
- 재시도·네트워크 오류가 데이터 중복을 발생시키지 않도록 한다.
- 계약 조건과 정산 내역의 변경 이력을 보존한다.

## 14.5 테스트 환경

- 교육 프로젝트에서는 PG sandbox를 사용한다.
- 실제 금전 거래를 수행하지 않는다.
- 모의 정산을 실제 송금 또는 법적 의미의 에스크로 서비스로 표시하지 않는다.
- 외부 서비스 연동 실패에 대한 재시도·오류 안내를 제공한다.
- 실제 배포 환경에서 사용자 역할별 핵심 플로우를 검증한다.

# 16. MVP 개발 전략 및 일정

## 16.1 개발 전략

B2C 전환을 위해 기존 프로젝트 구조를 전면 재구축하지 않는다.

**전략 1. 기존 RFP 필수 기능을 유지한다.**

기본 회원 관리, 공개 프로젝트, 지원·매칭, 계약, 결제 및 정산은 기존 설계와 개발 성과를 재사용한다.

**전략 2. 고객에게 보여주는 서비스 경험을 바꾼다.**

브랜드와 광고 프로젝트 중심 화면에서 개인 영상 작품과 제작 패키지 중심 화면으로 재구성한다.

**전략 3. 신규 개발을 최소화한다.**

기존 직접 의뢰 구조를 활용하고, 신규 데이터 구조는 필수 항목부터 추가한다.

**전략 4. 핵심 거래 흐름을 우선 완성한다.**

일정에 따라 고급 필터, 복잡한 옵션, AI 영상 편집 등은 후속으로 이관한다.

# 18. 협업 및 문서 관리

## 18.1 담당 범위

| 담당       | 주요 책임                                                 |
| ---------- | --------------------------------------------------------- |
| PM         | 제품 방향, PRD, 고객 문제, UX, 변경 요구사항, 문서 정합성 |
| 프론트엔드 | 작품 탐색·의뢰·거래 화면, API 연동, 사용자 상태 표시      |
| 백엔드     | DB·API·인증·거래 상태·파일·결제 처리                      |
| 팀 전체    | 구현 범위 합의, 통합 테스트, QA, 발표 준비                |

## 18.2 문서 간 관계

**PRD → 기능명세서 → ERD 및 API 명세 → 개발 → QA**

- **PRD:** 무엇을 왜 만드는가?
- **기능명세서:** 각 기능이 어떻게 동작해야 하는가?
- **ERD:** 어떤 데이터를 저장하고 관계를 정의하는가?
- **API 명세서:** 프론트엔드와 백엔드가 어떻게 상호작용하는가?
- **QA 문서:** 실제 구현이 요구사항을 충족하는가?

## 18.3 변경 관리 원칙

1. 기존 구현 완료 기능을 먼저 확인한다.
2. B2C 전환으로 달라지는 기능을 식별한다.
3. 데이터 및 API 변경이 필요한 항목은 기술 담당자와 검토한다.
4. 이미 합의된 계약·인증·결제 정책은 별도 승인 없이 임의로 변경하지 않는다.
5. 필수 기능이 지연되면 P1 기능부터 제외한다.
6. 변경 이유와 영향 범위를 문서로 남긴다.

## 19.2 후속 검증 사항

- [ ] 1만~5만 원대 상품별 실제 제작 원가 및 소요 시간
- [ ] 크리에이터의 패키지별 공급 가능 여부
- [ ] 개인 SNS 영상의 반복 구매 의사
- [ ] 신규 서비스의 주문 편의성 및 구매 전환
- [ ] 실제 결제·환불·정산 운영 정책
- [ ] 파일 보관 및 삭제 정책
- [ ] RFP 원본과 최신 기능명세서 정합성

위 사항은 제품 요구사항의 존재와 사업적 가설을 구분하기 위한 관리 항목이다. 사용자 인터뷰 및 실거래 검증 없이 시장성이 입증된 것으로 표시하지 않는다.

## 19.3 팀 합의가 필요한 구현 사항

- [ ] 기존 서비스의 사용자 노출 용어 변경 범위
- [ ] 포트폴리오·제작 패키지 신규 데이터 구조
- [ ] 직접 의뢰 화면의 실제 백엔드 연결 범위
- [ ] 기존 브랜드용 프로필 항목의 화면 처리
- [ ] 카테고리·스타일 분류값 변경
- [ ] RFP 필수 기능과 B2C 시연 기능의 구현 일정
- [ ] 최종 시연의 대표 사용자 시나리오

제품의 B2C 방향과 별개로, 이미 팀이 확정한 기술 정책의 변경에는 팀 합의가 필요하다.

## KEMI Product Vision

### Great Chemistry Makes Great Content

**KEMI는 크리에이터를 찾는 서비스가 아니라, 내가 원하는 영상을 찾는 서비스다.**

결혼식에서 함께 웃을 영상, 아이의 첫 생일을 기록할 영상, 부모님께 전할 감사의 영상, 여행의 순간을 담은 감각적인 릴스까지.

누군가에게는 특별한 추억이고 누군가에게는 평범한 일상인 순간을, 자신에게 맞는 크리에이터와 함께 하나의 콘텐츠로 완성한다.

**일상의 작은 영상부터 인생의 특별한 순간까지, 누구나 부담 없이 영상을 만들 수 있도록.**

_KEMI — Great Chemistry Makes Great Content._
