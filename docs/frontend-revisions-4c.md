# 4-C 수정 요청·수정본·회차 (개발 Mock)

## 근거와 범위

원본 `케미 기능명세서.xlsx` 기능 시트 REV-01(45행), REV-02(46행), 정책 P14(19행), D11(37행), 계획 §4단계 2·4항과 기능표를 대조했다. 여러 체크 항목은 한 요청, 일반 수정본 제출 시 한 회 완료, 초안·계약 오류는 별도다. 요청·채팅·조회·파일 준비는 차감하지 않는다. 승인·최종 전달·수령·정산은 이번 범위 밖이다.

`docs/api문서.txt`, `apps/api`, `packages/shared`에는 대응 경로/DTO가 없다. 기존 DEV/MSW `/__mock__/deliveries/:contractId` 안에 요청과 수정본을 같은 메모리 기록으로 보관해 원자적으로 연결한다. 실제 API/shared는 수정하지 않는다. 새로고침·다중 탭·영구 저장·실제 파일/권한·서버 시각·알림은 미검증이다.

## 구현 계획과 검증 기준

1. `revision-model.ts`, `delivery-model.ts`, `delivery-handlers.ts`: 당사자·대상 버전·요청·회차를 원자적으로 갱신한다. 단위 검사로 권한, 구버전, 혼합, 초과, 중복 ID/내용 충돌, 준비 보류, 오류 별도 처리를 확인한다.
2. `RevisionRequestForm.tsx`, `RevisionPanelMock.tsx`, 기존 제출 화면: 시간 위치·문제·희망 변경·참고 체크리스트, 요청 원문/처리 설명/수정본·원영상 바로가기, 재조회/같은 ID 재시도를 구현한다. 브라우저에서 요청→새 수정본→1회 완료와 오류/초안 0회·안내를 검증한다.
3. `e2e/revisions.spec.ts`, `qa/frontend-4c/`: 공개 제안/양측 서명/결제/준비/기존 영상부터 4-C 통합을 확인한다. 기존 4-B·준비·채팅 연관 회귀, 운영 DEV 제외, 타입/린트/형식/토큰/빌드를 확인한 후 커밋·푸시·Draft PR로 전달한다.

## 미결정과 Mock 경계

- P14 계약별 횟수/범위는 서명 조건의 자유 텍스트를 자동 파싱하지 않는다. 원문을 함께 표시하고 양측이 같은 구조화 **Mock 예시** 횟수/범위를 확인해야 일반 수정이 가능하다. 이 확인은 실제 계약 변경·추가 합의/전자서명이 아니다. 기본 한도를 임의 부여하지 않는다.
- D11 혼합(촬영/편집/오류), 수정본 납기, 요청 중 변경·승인은 확정하지 않는다. 한 요청은 한 분류·한 작업 분야로 제한하는 보수적 Mock 예시이며 혼합·추가 작업은 협의 안내로 보류한다. 요청 편집/취소·승인은 제공하지 않는다.
- 의뢰인이 계약 오류라고 등록해도 자동 확정하지 않는다. 제작자가 오류 시정에 동의해야 무차감 수정본 제출 가능하다. 이견 상태는 보류하며 횟수 소진만으로 오류 요청을 거절하지 않는다. 일반 요청은 구조화 Mock 범위 확인이 필요하고, 동시 진행 요청 1개 제한은 개발 경쟁 방지 예시다.
- 입력 보호 예시: 20항목, 항목별 텍스트 1000자, 시간 0~86400초, 횟수 0~20. 실제 정책 한도가 아니다. 영상 재생 시간 메타데이터로 UI에서 시간 위치를 확인하며 실제 서버의 미디어 길이 검증은 없다. 참고는 이스케이프 텍스트이며 외부 URL을 자동 요청하지 않는다.
- 실패/유실: 화면은 새 명령을 잠그고 재조회 또는 동일 ID/내용 재시도로 복구한다. Mock 저장소는 ID·행위자·내용, 최신 revision/대상 버전/준비 상태를 재확인한다. 성공한 저장본에서만 시스템 안내를 파생한다.
- 인증/권한: 본인 양측 서명 계약과 Bearer/세션 epoch를 본문 처리 뒤에도 재확인한다. 요청/미디어/안내는 당사자만 조회한다. 시간 이동은 선택 영상/요청의 URL에만 적용한다.

## 기술 확인

기술 PDF와 현행 Workspaces의 React/Vite, React Router, TanStack Query, Axios, Zod·기존 공통 UI/토큰을 따른다. 의존성 추가 없음. [Query mutation](https://tanstack.com/query/latest/docs/framework/react/reference/functions/useMutation)의 비자동 재시도와 [React key 기반 상태 초기화](https://react.dev/learn/preserving-and-resetting-state)를 설치 버전/기존 패턴과 대조했다.

## 실패 사전 점검

중복/경쟁은 같은 저장소의 revision과 영수증으로 차단한다. 응답 유실은 결과 확인 중으로 표시하고 차감/안내를 추측하지 않는다. 역할/로그아웃 변경은 epoch와 컴포넌트 key로 분리한다. 네트워크/형식 오류는 입력을 유지한다. 새로고침 복원·다중 탭·실제 서버 동시성은 이 메모리 Mock에서 보장하지 않으며 후속 실환경 검증으로 남긴다.
