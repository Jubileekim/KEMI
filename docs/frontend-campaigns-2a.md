# 2-A 캠페인 작성·임시 저장·공개

범위는 기능명세 CAMP-01/02, 정책 P06이다. `frontend-plan.md` 2단계 첫 항목 중 AI 분석은 후속 범위다. CAMP-03~06·제안·협의와 2단계 전체 완료를 포함하지 않는다.

## 근거와 계약 경계

- `케미 기능명세서.xlsx` 기능명세 CAMP-01/02: 제목·제품·목적·작업 범위·예산·참고 자료, 불완전 비공개 초안, 본인만 조회, 브랜드 정보 없이 공개.
- 정책 P06: 3/7/14일, 기본 7일. 공개 시각에서 해당 일수 뒤 같은 시각, 한국 시간 표시. 중복 공개로 마감을 재설정하지 않는다.
- D04는 미결정: 필수 입력·문자 수·예산 범위·공개 후 변경/삭제 범위. 이번 모의 공개 검사는 제목·제품·목적·작업 범위·양의 정수 예산을 후보로 사용한다. 각 문자열 4,000자·안전한 정수 보호는 Mock 입력 보호용이며 합의한 제품 정책이 아니다. 참고 자료는 선택 텍스트다. 파일 업로드/외부 링크 방문은 연결하지 않는다.
- `docs/api문서.txt` 470~571행, `packages/shared/src/project.ts`, `apps/api/src/projects/project.service.ts` 대조: POST는 즉시 OPEN이며 DRAFT/초안 조회·수정/별도 공개/공개 기준 모집 일수 계약이 없다. 제품·작업 범위·참고 자료에 대응하는 필드도 없다. 기존 purpose enum을 제품 분야와 동일시하지 않는다. 기존 API의 제목 2~200/설명 10~5000/예산 상한·납품일 검사는 D04 확정 근거가 아니다.
- 따라서 실제 `/api/projects`를 호출하지 않고 개발 전용 `/__mock__/campaigns`로 분리한다. 운영은 계약 준비 안내를 표시한다. API/shared·DB 계약을 변경하지 않는다.

## 실패 설계

- 실패·지연: 저장 응답을 검증한 뒤에만 성공 표시. 처리 중 중복 행동/편집 금지, 자동 재시도 없음. 오류 시 폼 유지. 조회 실패도 기존 입력을 덮어쓰지 않는다.
- 응답 유실: 공개 결과가 불명확하면 최신 값 확인을 안내한다. 동일 ID 공개 재전송은 기존 공개/마감 시각을 유지한다.
- 계정 변경: 요청 전후 epoch 확인·Query 캐시 분리, Mock handler의 Bearer/본인/역할/ACTIVE 재검증. 지연 도중 계정이 바뀌면 쓰지 않는다.
- 경쟁 변경: revision 충돌 시 최신 값 확인과 명시적 재저장. 실제 서버 원자성·다중 탭은 검증 경계 밖이다.
- 데이터 수명: 탭 내 메모리만 사용하고 전체 새로고침 시 초기화한다. DB/영구 저장·실제 공개 목록/API·마감 자동 상태 전이는 미연결이다.
- 날짜: 공개 시 처리 시각을 기준으로 계산하고 Asia/Seoul로 표시한다. 미리보기 날짜는 예상이며 서버 확정 날짜로 표시하지 않는다.
