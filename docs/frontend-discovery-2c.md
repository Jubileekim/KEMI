## 작업·실패 설계

1. 공개 투영·필터/안정 정렬/페이지·정각 마감 판정·소유자/활성 역할/revision/멱등 마감 모델을 단위 검증한다.
2. 목록/상세/확인창을 연결하고 검색 조건은 URL에 보관한다. 입력 수정 후 명시 검색 시 페이지1, 상세 왕복·뒤로 가기·새로고침에 검색 조건 유지. 잘못된 URL은 오류/초기화, 범위 밖 페이지는 첫 페이지 이동을 제공한다.
3. 자동 재시도 없음. 실패는 로컬 문구, 재조회 실패 시 오래된 상세 변경 행동을 숨긴다. 변경 응답 유실은 최신 상태 확인으로 해소한다. 중복 마감과 재공개로 기한/내용을 바꾸지 않는다. epoch/Bearer/활성 소유자 재검사·Query 캐시 분리로 계정 변경 후 지연 쓰기를 막는다.
4. 기한 도달 시 클라이언트 유효 상태는 마감으로 표시하고 행동을 차단한다. 목록은 페이지/상태 필터 밖 공고까지 포함한 Mock 응답의 다음 기한에 재조회하여 결과 수를 갱신한다. 브라우저 시간은 실제 서버 자동 전이·신규 제안 거절·다중 탭·원자성 보장이 아니다. 제안 기능은 아직 연결 준비 중이며 마감 시 신규 제안 종료로 표시한다.
5. 마감 모델은 공고 상태만 변경한다. 기존 협의·서명·계약의 실제 유지 및 관련자 알림은 해당 API/후속 단계의 실환경 검증이 필요하다. 이번에 존재하지 않는 거래를 만들어 유지 검증했다고 주장하지 않는다.
