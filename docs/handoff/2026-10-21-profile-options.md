# 프로필 선택지 공유 (프론트엔드용)

- 대상: 프로필 작성·수정 화면 (PROFILE-01 의뢰인, PROFILE-02 크리에이터)
- API: `GET /api/profiles/me`, `PATCH /api/profiles/me` (PR #13). 응답·요청 형식은 Swagger(`/api/docs`)에서 확인할 수 있다.
- 상태: **임시 값이다.** 분야와 콘텐츠 스타일은 D21이 정해지지 않아 ERD v0.5 값을 쓴다. 값이 바뀌면 이 문서와 `@kemi/shared`를 함께 고친다.
- 근거: [결정 기록](../decisions/2026-10-19-backend-setup.md) 10장

## 값 가져오기

선택지 목록을 화면 코드에 다시 적지 말고 `@kemi/shared`에서 가져온다. 서버 검증과 DB CHECK가 같은 배열을 쓰므로 값이 바뀌어도 한 곳만 고치면 된다.

```ts
import {
  CONTENT_STYLES, // 콘텐츠 스타일
  PRODUCT_CATEGORIES, // 제품 분야 (의뢰인 industry, 크리에이터 niche)
  PRODUCTION_ROLES, // 제작 역할
  type ContentStyle,
  type ProductCategory,
  type ProductionRole,
} from "@kemi/shared";
```

- API에는 아래 **값**(영문 대문자)을 보내고 받는다. 화면에는 **표시 이름**을 보여준다.
- 표시 이름은 서버가 내려주지 않는다. 화면에서 값 → 표시 이름 표를 둔다.

## 제품 분야 [임시 · D21]

의뢰인의 `industry`(제품 분야), 크리에이터의 `niche`(주 분야)에 쓴다. 하나만 고른다. 선택 안 함은 `null`이다.

| 값          | 표시 이름 [제안] |
| ----------- | ---------------- |
| `BEAUTY`    | 뷰티             |
| `FOOD`      | 식품             |
| `LIFESTYLE` | 라이프스타일     |
| `TECH`      | 테크·가전        |
| `OTHER`     | 기타             |

## 콘텐츠 스타일 [임시 · D21]

크리에이터의 `contentStyles`. 여러 개를 고를 수 있다. 같은 값을 두 번 넣으면 400이다. 아무것도 고르지 않으면 `[]`다.

| 값             | 표시 이름 [제안] |
| -------------- | ---------------- |
| `MODERN`       | 모던             |
| `BRIGHT`       | 밝고 경쾌한      |
| `EMOTIONAL`    | 감성적인         |
| `PROFESSIONAL` | 전문적인         |
| `OTHER`        | 기타             |

## 제작 역할

크리에이터의 `productionRoles`. 여러 개를 고를 수 있다. 규칙은 콘텐츠 스타일과 같다. 표시 이름은 PRD 6.2·7.4(기획·출연·촬영·편집)를 따른다.

| 값          | 표시 이름 |
| ----------- | --------- |
| `PLANNING`  | 기획      |
| `ON_CAMERA` | 출연      |
| `FILMING`   | 촬영      |
| `EDITING`   | 편집      |

## 제작 서비스 상태 (읽기 전용)

크리에이터 응답의 `serviceStatus`. 프로필 저장으로는 바뀌지 않으며, 요청에 넣으면 400이다. 공개·비공개 전환(PROFILE-03·04)은 패키지 기능과 함께 만든다.

| 값        | 표시 이름 [제안] |
| --------- | ---------------- |
| `DRAFT`   | 작성 중 (비공개) |
| `PUBLIC`  | 공개             |
| `PRIVATE` | 비공개           |

## 저장 규칙 (PATCH 값 규칙)

결정 기록 10장 "PATCH 값 규칙" 표와 같은 내용이며, 서버 테스트(`profiles.db.test.ts`의 "PATCH 값 규칙")가 이 표의 칸마다 확인한다. 바꾼 항목만 보내면 되고, 보내지 않은 항목은 그대로다.

| 항목 종류                                              | 보내지 않음 | 빈 문자열 `""`·공백만 | `null` | 그 외 값                                                      |
| ------------------------------------------------------ | ----------- | --------------------- | ------ | ------------------------------------------------------------- |
| 선택 문자열: `brandName`, `introduction`, `workMethod` | 그대로      | `null`로 저장 (지움)  | 지움   | 앞뒤 공백을 지우고 저장. 길이 초과는 400                      |
| 선택 주소: `websiteUrl`, `socialUrl`                   | 그대로      | `null`로 저장 (지움)  | 지움   | http/https 주소만 저장, 아니면 400                            |
| 선택지 하나: `industry`, `niche`                       | 그대로      | 400                   | 지움   | 허용 값만 저장, 아니면 400                                    |
| 복수 선택: `contentStyles`, `productionRoles`          | 그대로      | 400                   | 400    | 배열 전체를 바꾼다. `[]`이면 모두 지움. 중복·허용 밖 값은 400 |
| 날짜: `availableFrom`                                  | 그대로      | 400                   | 지움   | `YYYY-MM-DD`만 저장, 아니면 400                               |
| 참·거짓: `isAvailable`                                 | 그대로      | 400                   | 400    | `true`·`false`                                                |
| 표시 이름: `name`                                      | 그대로      | 400                   | 400    | 앞뒤 공백을 지우고 2~20자                                     |

- 빈 문자열을 `null`로 바꾸는 것은 자유 입력 칸(문자열·주소)뿐이다. 선택지·날짜는 화면에서 "선택 안 함"을 `null`로 보낸다.
- 길이 제한: 브랜드명 50자, 소개·작업 방식 1000자. DB는 길이를 검사하지 않고 API가 검사한다.
- `availableFrom`은 `YYYY-MM-DD` 문자열이다.
- 다른 역할의 항목을 보내면 400이다. 예: 크리에이터가 `brandName`을 보내는 경우.
- 400이면 아무것도 저장되지 않는다. `error.details`에 문제가 된 항목의 경로(`path`)와 메시지가 들어 있다.

## 확인 요청

- 표시 이름 [제안] 문구가 화면 기획과 맞는지
- 분야·스타일 목록 자체(D21)는 기획 확정 후 알려주면 백엔드가 shared·DB를 함께 바꾼다
