# KEMI 기능 → 프론트엔드 개발 대응표

작성일: 2026-10-23. 원본 엑셀의 기능 69개를 행 순서대로 모두 대응한다. 단계·화면·폴더는 새 계획의 제안이며, 완료 기준·정책 구분·정책 ID는 원본 값이다. 모든 기능의 현재 구현 상태는 미착수다. 원본 엑셀은 수정하지 않았다.

기술 기준은 `기술 스택.pdf`이며 앱 경로는 `apps/web/`, 담당 폴더 열은 `apps/web/src/` 내부 상대 경로다. 기술 스택 반영으로 기능·단계·API 판정은 변경하지 않았다.

기준: `../케미 기능명세서.xlsx`의 `기능명세!A6:S74`. 화면 ID와 단계는 `frontend-plan.md` 참조. 각 행의 실제 API·외부 제공자 검증은 계획 8단계의 공통 관문을 추가 적용한다.

## API 문서 대조 기준 (2026-10-23 추가)

참고 자료: `api문서.txt` (OpenAPI 3.1 문서를 만드는 TypeScript 소스, 26개 경로·33개 동작). **명세 일치**는 문서에 드러난 동작 수준에서 주요 의미가 맞는다는 뜻이며, 구현·실서버·전체 입력 스키마 검증 완료를 뜻하지 않는다. `@kemi/shared`의 enum과 요청 스키마 원본이 없어 정확한 필드·선택값은 추가 확인해야 한다.

- **수정 필요:** 일부 API만 있거나, 명세와 충돌하거나, 필수 동작의 문서화/정의 보완이 필요하다. 서버 구현 자체의 오류로 단정하지 않는다.
- **API 정의 없음:** 이 파일에서 해당 기능을 수행하는 경로/동작을 찾지 못했다. 다른 서버 코드에도 없다는 뜻은 아니다.
- P/D 정책은 엑셀이 기준이다. API의 구체적 설계가 D 미결정을 자동으로 확정하지 않는다. 불일치 기능은 합의 전 Mock으로 분리하고 실제 완료로 표시하지 않는다.
