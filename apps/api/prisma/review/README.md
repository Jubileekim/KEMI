# KEMI ERD v0.5 / PRD v1.4 데이터베이스 검토

작성일: 2026-10-19
상태: ERD 변환본 검증 완료. PRD 반영 및 팀 검토 전 DB 적용 금지.

## 완료 사항

- Downloads의 KEMI_schema_v0_5.prisma를 prisma/schema.prisma에 반영하였다.
- 이전 기본 스키마는 prisma/schema.before-v0_5.prisma.bak에 보존하였다.
- Prisma 7.10.1 validate 및 generate가 통과하였다.
- prisma7.config.ts를 Prisma가 자동 탐색하는 prisma.config.ts로 변경하였다. 연결 설정 내용은 유지하였다.
- .env는 ignore 규칙에 해당하며 현재 Git 추적 파일 및 해당 경로의 로컬 Git 이력에 나타나지 않았다. 원격 GitHub 전체의 과거 유출 여부를 입증하는 검사는 아니다.
- erd-v0_5.unapplied.sql은 빈 데이터베이스를 가정한 오프라인 비교 결과이다. 실제 Supabase 상태와 비교한 마이그레이션이 아니며 실행하지 않았다.

## Prisma 문법 검사 밖에서 구현할 제약

1. 공개 지원은 project_id 필수, 직접 의뢰는 NULL. 패키지·의뢰·공고의 소유자와 당사자가 일치해야 한다.
2. 같은 캠페인·크리에이터의 활성 지원은 최대 1건이다. 부분 고유 인덱스 또는 동등한 DB 제약을 검토한다.
3. 캠페인당 확정 계약은 최대 1건이다. 다른 후보의 동시 서명을 트랜잭션과 공고 잠금/고유 제약으로 차단한다.
4. 같은 유효 조건 버전에 당사자 양측 서명이 있어야 계약을 확정한다. 서명·모집 종료·미선정 처리·알림 outbox 기록은 원자적으로 처리한다.
5. 금액·수량·기한·별점 등 범위 CHECK, 결제·환불·정산의 금액 정합성, PG 이벤트 멱등성을 구현한다.
6. 원장·결제 사건은 추가 전용으로 유지하고 정정은 새 기록으로 남긴다. 분개별 차변·대변 합계와 통화를 검증한다.
7. updated_at의 default(now())는 갱신 시각을 자동 수정하지 않는다. Prisma @updatedAt 또는 DB trigger 중 적용 방식을 결정한다.
8. JSON의 계약 조건·브리프·태그는 서버에서 검증하며 필수 조건을 자유 텍스트만으로 대체하지 않는다.
9. BigInt ID와 금액은 JSON 응답에서 문자열로 직렬화하고 Number 변환에 따른 정밀도 손실을 방지한다.

## 접근 권한과 DB 적용 전 확인

- Supabase의 노출 스키마에는 RLS를 적용하고 Data API grants를 함께 확인한다. Prisma가 생성한 SQL에는 RLS 정책이 포함되지 않는다.
- users.id가 BigInt이므로 auth.uid()와 바로 비교하지 않는다. 자체 Express 인증과 Supabase Auth 중 사용할 구조를 먼저 확인하고, 필요하면 UUID 연결을 별도 정의한다.
- Express의 DB 연결 역할이 RLS를 우회할 수 있으므로 서버에서도 본인·역할·거래 당사자 권한을 검증한다.
- 비공개 파일은 영구 공개 URL 대신 비공개 bucket/object 경로로 보존하고 권한 확인 후 제한 시간 URL을 발급한다.
- 리뷰는 완료 계약의 당사자만 작성하고 본인 평가를 차단한다.
- 운영자는 일반 사용자 역할과 구분한 권한으로 관리한다.

공식 참고: https://supabase.com/docs/guides/api/securing-your-api
